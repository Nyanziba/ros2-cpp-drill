# 6. 構造体とアラインメント

> **この章のねらい**: `sizeof` が単純に「メンバのサイズの合計」ではない理由は、メモリアラインメントです。CPU が効率よくアクセスするため、データ型ごとに開始アドレスが指定されます。その結果、メンバの並び順で構造体全体のサイズが変わります。マイコンのレジスタやネットワークプロトコルを扱う際、この知識は必須です。

## 6.1 メンバの並び順で `sizeof` が変わる

**メモリ内での位置は型で決まる。型ごとのアラインメント要求によって、中間に詰め物（パディング）が入る。**

```c
struct unordered {
    char a;      // 1 byte
    int b;       // 4 bytes (4-byte aligned)
    char c;      // 1 byte
};
```

`int` は 4-byte アラインメント要求なので、`a` の直後には 3 バイトの「詰め物」が入ります。

実測値：

```
struct unordered:  sizeof = 12
  offsetof(a) = 0
  offsetof(b) = 4
  offsetof(c) = 8
```

メモリレイアウト：

```
[0]a [1][2][3] padding [4-7]b [8]c [9][10][11] padding
```

**同じメンバを並び替えるだけで、サイズが縮む。**

```c
struct reordered {
    int b;       // 4 bytes (4-byte aligned at offset 0)
    char a;      // 1 byte
    char c;      // 1 byte  (offset 5 に詰め込める)
};
```

実測値：

```
struct reordered:  sizeof = 8
  offsetof(b) = 0
  offsetof(a) = 4
  offsetof(c) = 5
```

メモリレイアウト：

```
[0-3]b [4]a [5]c [6][7] padding
```

同じメンバなのに、`unordered` は 12 バイト、`reordered` は 8 バイト。**並び順が重要です。**

## 6.2 `offsetof` と `_Alignof`

**`offsetof(struct_name, member_name)` はメンバの開始位置をバイト単位で返す。**

```c
#include <stddef.h>

struct unordered {
    char a;
    int b;
    char c;
};

offsetof(struct unordered, a);  // 0
offsetof(struct unordered, b);  // 4
offsetof(struct unordered, c);  // 8
```

**`_Alignof(type)` は型のアラインメント要求を返す。**

実測値：

```
_Alignof(char) = 1
_Alignof(int) = 4
_Alignof(struct unordered) = 4
```

構造体のアラインメント要求は「最大のメンバのアラインメント要求」になります。`int` が 4-byte アラインメント要求なので、構造体全体も 4-byte です。

## 6.3 `#pragma pack` と `__attribute__((packed))` — パディングを削除

**パディングなしで、メンバを詰め詰めに配置したい場合、`__attribute__((packed))` を使う。**

```c
struct packed_attr {
    char a;
    int b;
    char c;
} __attribute__((packed));
```

実測値：

```
struct packed_attr: sizeof = 6
  offsetof(a) = 0
  offsetof(b) = 1
  offsetof(c) = 5
  _Alignof = 1
```

メモリレイアウト：

```
[0]a [1-4]b [5]c
```

サイズが 12 から 6 に縮みました。パディングがなくなったからです。

**警告：未整列アクセスの危険。** 多くのマイコンでは、4-byte の値が 4-byte アラインされていないアドレスに置かれると、アクセス時にペナルティがあるか、クラッシュします。ネットワークプロトコル（バイト列で受け取ったデータを構造体に変換する）のように、確実に安全な場合だけ `packed` を使ってください。

```c
// ネットワークプロトコルの例（安全）
struct CAN_message {
    uint32_t id;      // ネットワークバイト順
    uint8_t dlc;
    uint8_t data[8];
} __attribute__((packed));
```

## 6.4 メンバ順を工夫して最適化

**大きい型を先に、小さい型をあとに。**

```c
// 悪い並び順：12 バイト
struct bad {
    char a;
    int b;
    char c;
    short d;
};

// よい並び順：8 バイト
struct good {
    int b;
    short d;
    char a;
    char c;
};
```

メモリを節約したい場合や、キャッシュ効率を考える際に、メンバの順序を整理する価値があります。

## 手元で試す

パディング、アラインメント、`offsetof`、`packed` を実際に確認します。

```c
// struct_all.c
#include <stdio.h>
#include <stddef.h>

struct unordered {
    char a;
    int b;
    char c;
};

struct reordered {
    int b;
    char a;
    char c;
};

struct packed_example {
    char a;
    int b;
    char c;
} __attribute__((packed));

int main(void)
{
    printf("== Padding and sizeof ==\n");
    printf("struct unordered:  sizeof = %zu\n", sizeof(struct unordered));
    printf("  offsetof(a) = %zu\n", offsetof(struct unordered, a));
    printf("  offsetof(b) = %zu\n", offsetof(struct unordered, b));
    printf("  offsetof(c) = %zu\n", offsetof(struct unordered, c));

    printf("\nstruct reordered:  sizeof = %zu\n", sizeof(struct reordered));
    printf("  offsetof(b) = %zu\n", offsetof(struct reordered, b));
    printf("  offsetof(a) = %zu\n", offsetof(struct reordered, a));
    printf("  offsetof(c) = %zu\n", offsetof(struct reordered, c));

    printf("\n== _Alignof ==\n");
    printf("_Alignof(char) = %zu\n", _Alignof(char));
    printf("_Alignof(int) = %zu\n", _Alignof(int));
    printf("_Alignof(struct unordered) = %zu\n", _Alignof(struct unordered));

    printf("\n== __attribute__((packed)) ==\n");
    printf("struct packed_example: sizeof = %zu\n", sizeof(struct packed_example));
    printf("  offsetof(a) = %zu\n", offsetof(struct packed_example, a));
    printf("  offsetof(b) = %zu\n", offsetof(struct packed_example, b));
    printf("  offsetof(c) = %zu\n", offsetof(struct packed_example, c));

    struct unordered u;
    struct reordered r;
    struct packed_example p;

    printf("\n== In-memory sizes ==\n");
    printf("sizeof(u) = %zu (with padding)\n", sizeof(u));
    printf("sizeof(r) = %zu (with less padding)\n", sizeof(r));
    printf("sizeof(p) = %zu (no padding)\n", sizeof(p));

    return 0;
}
```

**予想: `struct unordered` と `struct reordered` のサイズの差は何か。`offsetof(struct reordered, a)` は何か。**


## つまずきポイント

**`sizeof(struct)` が大きすぎる**
メンバが大きい型を含むと、全体のアラインメント要求が上がり、パディングが増えます。メンバの順序を工夫してみてください。

**`offsetof` が予想と違う**
アラインメント要求によって、メンバの位置がずれます。`offsetof` で確認してください。

**`__attribute__((packed))` を使ったら、メンバへのアクセスが遅い / クラッシュする**
未整列アクセスです。`packed` は「バイト列として安全」な場合（ネットワークプロトコル、I/O メモリ）だけに限ってください。

**C99 では `_Alignof` がサポートされていない（警告）**
コンパイラ拡張です。GCC/Clang では `-Wpedantic` を外すか、`-std=gnu99` で大丈夫です。
