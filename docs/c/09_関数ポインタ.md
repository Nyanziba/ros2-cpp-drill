# 9. 関数ポインタ

> **この章のねらい**: 関数ポインタはコールバック、テーブル駆動ディスパッチ、ドライバの抽象化に活躍します。宣言の読み方、関数の減衰、NULL チェックの重要性を実装で学びます。

## 9.1 関数ポインタの宣言と読み方

**関数ポインタは括弧の位置で宣言が大きく異なります。**

```c
int (*fp)(int);      // int を取り int を返す関数へのポインタ
int *fp(int);        // int を取り int* を返す関数（ポインタではなく関数）
```

「宣言を読む」ときは、`*` がどこにあるかに注目します。

| 宣言 | 読み方 | 意味 |
| --- | --- | --- |
| `int (*fp)(int)` | `(*fp)` は関数ポインタ | `int` を取り `int` を返す関数へのポインタ |
| `int *fp(int)` | `fp(int)` は関数 | `int` を取り `int*` を返す関数 |

括弧の位置次第で、「ポインタ」と「ポインタを返す関数」が逆転します。

## 9.2 関数名の減衰

**C では関数名は自動的に関数ポインタに減衰します。** `&func` と `func` の両方が有効です。

```c
int add(int a, int b) {
    return a + b;
}

typedef int (*Operation)(int, int);

Operation op1 = add;      // 減衰
Operation op2 = &add;     // 明示的なアドレス取得
```

どちらでも同じです。後者のほうが意図が明確ですが、慣例的には前者をよく見かけます。

```c
printf("op1(3, 4) = %d\n", op1(3, 4));    // 7
printf("(*op2)(3, 4) = %d\n", (*op2)(3, 4));  // 7
```

どちらの呼び出し方も可能です。

## 9.3 typedef で読みやすく

**関数ポインタ型は複雑なので、`typedef` で別名をつけると読みやすくなります。**

```c
typedef int (*Handler)(int param);

Handler h = some_function;
h(42);
```

`typedef` がない場合は以下のようにくどくなります。

```c
int (*h)(int param) = some_function;  // 読みにくい
h(42);
```

実務では必ず `typedef` をつけます。

## 9.4 コールバック：qsort の例

**C の標準ライブラリ `qsort` は、比較関数をコールバックとして受け取ります。**

```c
#include <stdlib.h>

int cmp_asc(const void *a, const void *b) {
    return *(int *)a - *(int *)b;
}

int cmp_desc(const void *a, const void *b) {
    return *(int *)b - *(int *)a;
}

int main(void)
{
    int arr[] = {5, 2, 8, 1, 9, 3};
    int n = sizeof(arr) / sizeof(arr[0]);

    qsort(arr, n, sizeof(int), cmp_asc);
    // arr[] = {1, 2, 3, 5, 8, 9}

    qsort(arr, n, sizeof(int), cmp_desc);
    // arr[] = {9, 8, 5, 3, 2, 1}
    return 0;
}
```

比較関数を渡すだけで、同じ `qsort` が昇順・降順に対応します。これが**ポリモーフィズム**の基本形です。

## 9.5 テーブル駆動ディスパッチ

**コマンド処理は switch 分で拡張困難です。関数ポインタの配列（テーブル駆動）なら、ハンドラを追加するだけです。**

```c
typedef int (*Handler)(int param);

typedef struct {
    int id;
    Handler handler;
} CommandEntry;

int handle_start(int param) { ... }
int handle_stop(int param) { ... }
int handle_reset(int param) { ... }

CommandEntry cmd_table[] = {
    {1, handle_start},
    {2, handle_stop},
    {3, handle_reset},
    {0, NULL}  // 終端マーク
};

int dispatch_command(int cmd_id, int param) {
    for (int i = 0; cmd_table[i].handler != NULL; i++) {
        if (cmd_table[i].id == cmd_id) {
            return cmd_table[i].handler(param);
        }
    }
    return -1;  // 未知コマンド
}
```

実行時の流れ：`dispatch_command(1, 100)` → `cmd_table` を走査 → `handle_start` を呼ぶ。

マイコンのコマンドディスパッチがまさにこの形です。

## 9.6 NULL 関数ポインタの危険性

**未登録（NULL）の関数ポインタを呼ぶと、即座に Segmentation Fault でクラッシュします。** これが実務で最も刺さる点です。

```c
typedef int (*Handler)(int);

Handler h = NULL;

// 以下は絶対に呼ぶな！
// int result = h(42);  // ← Segmentation Fault
```

**必ず NULL チェックしてから呼ぶ：**

```c
if (h != NULL) {
    int result = h(42);
} else {
    printf("Handler is not registered\n");
}
```

テーブルからハンドラを探すときも同じです。

```c
int dispatch_command(int cmd_id, int param) {
    for (int i = 0; cmd_table[i].handler != NULL; i++) {
        if (cmd_table[i].id == cmd_id) {
            // ここで handler は必ず NULL 以外
            return cmd_table[i].handler(param);
        }
    }
    // 見つからなかった場合の処理
    return -1;
}
```

終端に `{0, NULL}` を置くことで、ループを安全に終了させます。

## 9.7 構造体にハンドラを持たせてドライバを抽象化

**複数のデバイスに同じインターフェースを提供するとき、構造体にハンドラを詰め込みます。**

```c
typedef struct {
    int (*open)(void);
    int (*read)(void);
    int (*write)(int);
    int (*close)(void);
} DeviceOps;

// Device A と Device B は異なる実装を持つが、
// 同じ DeviceOps インターフェースで操作可能
DeviceOps dev_a = {
    .open = device_a_open,
    .read = device_a_read,
    .write = device_a_write,
    .close = device_a_close
};

// 同じコードで両方のデバイスを操作
dev_a.open();
int val = dev_a.read();
dev_a.write(val + 10);
dev_a.close();
```

モータドライバ、CAN トランシーバ、センサーなど、デバイス固有の実装を隠蔽する定番パターンです。

## 手元で試す

関数ポインタの全機能を実演するコードです。

```c
// func_pointer_all.c
#include <stdio.h>
#include <stdlib.h>

typedef int (*Operation)(int, int);
typedef int (*Handler)(int);

// 演算関数
int add(int a, int b) { return a + b; }
int multiply(int a, int b) { return a * b; }
int subtract(int a, int b) { return a - b; }

// コマンドハンドラ
int handle_start(int param) { printf("  [START] param=%d\n", param); return 0; }
int handle_stop(int param) { printf("  [STOP] param=%d\n", param); return 0; }
int handle_reset(int param) { printf("  [RESET] param=%d\n", param); return 0; }

// テーブル駆動のコマンドエントリ
typedef struct {
    int id;
    Handler handler;
} CommandEntry;

CommandEntry cmd_table[] = {
    {1, handle_start},
    {2, handle_stop},
    {3, handle_reset},
    {0, NULL}
};

int dispatch_command(int cmd_id, int param) {
    for (int i = 0; cmd_table[i].handler != NULL; i++) {
        if (cmd_table[i].id == cmd_id) {
            return cmd_table[i].handler(param);
        }
    }
    printf("  Unknown command: %d\n", cmd_id);
    return -1;
}

// qsort 用の比較関数
int cmp_asc(const void *a, const void *b) {
    return *(int *)a - *(int *)b;
}

int cmp_desc(const void *a, const void *b) {
    return *(int *)b - *(int *)a;
}

int main(void)
{
    printf("== 関数ポインタ: 減衰と typedef ==\n");
    Operation op1 = add;      // 減衰
    Operation op2 = &multiply;
    printf("op1(3, 4) = %d\n", op1(3, 4));
    printf("op2(3, 4) = %d\n", op2(3, 4));
    printf("\n");

    printf("== コールバック: qsort ==\n");
    int arr[] = {5, 2, 8, 1, 9, 3};
    int n = sizeof(arr) / sizeof(arr[0]);
    printf("元の配列: ");
    for (int i = 0; i < n; i++) printf("%d ", arr[i]);
    printf("\n");

    qsort(arr, n, sizeof(int), cmp_asc);
    printf("昇順: ");
    for (int i = 0; i < n; i++) printf("%d ", arr[i]);
    printf("\n");

    qsort(arr, n, sizeof(int), cmp_desc);
    printf("降順: ");
    for (int i = 0; i < n; i++) printf("%d ", arr[i]);
    printf("\n\n");

    printf("== テーブル駆動ディスパッチ ==\n");
    dispatch_command(1, 100);
    dispatch_command(2, 200);
    dispatch_command(3, 300);
    dispatch_command(99, 400);
    printf("\n");

    printf("== NULL チェック ==\n");
    Handler h = NULL;
    if (h != NULL) {
        h(42);
    } else {
        printf("Handler is NULL. Calling it would crash.\n");
    }
    printf("\n");

    printf("完了\n");
    return 0;
}
```

**予想: qsort が昇順・降順に対応して並び替わるか。テーブルディスパッチが正しいハンドラを呼ぶか。NULL チェックが機能するか。**

```bash
gcc -std=c99 -Wall -Wextra -Wpedantic func_pointer_all.c -o func_pointer_all && ./func_pointer_all
```

## つまずきポイント

**括弧の位置を混同する**
`int (*fp)(int)` と `int *func(int)` は全く異なります。括弧の位置をよく確認。

**NULL チェック忘れでクラッシュ**
見つからないハンドラを呼ぶと Segmentation Fault。設計時に NULL チェック箇所を明示してください。

**型が合わない**
コールバック関数の型が異なるとコンパイラがエラー。`typedef` で型を明確に。

**qsort 比較関数でオーバーフロー**
`return a - b;` は大きい値でオーバーフロー。比較を `if` で分けるほうが安全。
