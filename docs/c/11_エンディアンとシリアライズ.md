# 11. エンディアンとシリアライズ

> **この章のねらい**: バイト列を扱う通信・ログ保存では、「複数バイトを持つ値（`float` や `uint32_t`）を何番目のバイトから詰めるか」が重要です。リトルエンディアン・ビッグエンディアンの違いと実測方法を理解した上で、値とバイト列の相互変換を `memcpy` で安全に行う方法を身に付けます。部内の CAN プロトコル実装が示す「ポインタキャスト（`*(uint32_t *)&f`）は避け、`char` の符号性に注意して `memcpy` を使う」という実装パターンが、なぜ必要か、を理解することが目的です。

## 11.1 バイト順とは何か

**多バイト整数はメモリのどちらから始まるか。**

`uint32_t x = 0x12345678;` が手元のメモリに格納されるとき、4 つのバイトはこのように配置されます。

リトルエンディアン（低位バイトが先）：
```
x[0] = 0x78, x[1] = 0x56, x[2] = 0x34, x[3] = 0x12
```

ビッグエンディアン（高位バイトが先）：
```
x[0] = 0x12, x[1] = 0x34, x[2] = 0x56, x[3] = 0x78
```

**通信やファイル保存では、どちらのバイト順で相手に送るか、を明確にしなければ通じません。** 部内の CAN プロトコルは「リトルエンディアン固定」と仕様に明記しています。

## 11.2 手元の環境を実測する

ポインタキャスト（未定義動作の危険）ではなく、`memcpy` で安全に値をバイト列に変換し、どちらのバイト順か確かめます。

**「1 つの値を複数バイトに詰める」の基本**

```c
#include <stdint.h>
#include <string.h>

uint32_t val = 0x12345678;
unsigned char bytes[4];

/* unsafe: *(uint32_t *)&bytes[0] = val;  ← 厳密エイリアシング違反 */
memcpy(bytes, &val, 4);  /* ← これが正解 */

printf("%02x %02x %02x %02x\n", bytes[0], bytes[1], bytes[2], bytes[3]);
```

実測値：
```
78 56 34 12
```

`bytes[0]` が `0x78`（最下位バイト）なので、**この環境はリトルエンディアン**です。

## 11.3 多バイト値をバイト列に詰める / 取り出す

**リトルエンディアンで、シフトとマスクを使い、明示的にバイトを並べる。**

### バイト列から uint32_t を組み立てる

```c
uint32_t read_uint32_le(const unsigned char data[4]) {
    return (uint32_t)data[0] |
           ((uint32_t)data[1] << 8) |
           ((uint32_t)data[2] << 16) |
           ((uint32_t)data[3] << 24);
}
```

バイト[0]が最下位、バイト[3]が最上位です。

### uint32_t をバイト列に分解する

```c
void write_uint32_le(uint32_t value, unsigned char out[4]) {
    out[0] = (unsigned char)(value & 0xFF);
    out[1] = (unsigned char)((value >> 8) & 0xFF);
    out[2] = (unsigned char)((value >> 16) & 0xFF);
    out[3] = (unsigned char)((value >> 24) & 0xFF);
}
```

各バイトを右シフトとマスクで抽出し、キャストで `unsigned char` に詰めます。

## 11.4 ポインタキャストは厳密エイリアシング違反

**「型パン」—— 危険な書き方と正しい書き方。**

よく見かける（**ダメな**）パターン：

```c
float f = 1.0f;
uint32_t u32_bad = *(uint32_t *)&f;  /* 未定義動作：型の詐称 */
```

C の厳密エイリアシングルール（strict aliasing）では、**`float` 型のメモリを `uint32_t *` でキャストして読むことは未定義動作**です。コンパイラは最適化時にこのバグに気付かず、予期しない値や実行時エラーが起こります。

**正しい書き方：`memcpy` を使う。**

```c
float f = 1.0f;
uint32_t u32_good;
memcpy(&u32_good, &f, sizeof(f));  /* 安全：バイト単位のコピー */
```

`memcpy` はバイト単位で値をコピーするため、型システムの制約を受けません。コンパイラも最適化を安全に行えます。

## 11.5 char の符号性対策

**バイト列から広がる値への変換時は、`(unsigned char)` に通してから widening する。**

C では `char` が符号付きか符号なしか処理系依存です。バイト値が `0x80` 以上のとき、`char` で読むと負の数に見え、それを `uint32_t` に広げると符号拡張で上位ビットが `1` で埋まります。

**符号拡張で壊れる例**

バイト列 `0x80, 0xFF, 0x00, 0x00` を `uint32_t` に読む場合：

```c
unsigned char raw[4] = {0x80, 0xFF, 0x00, 0x00};

/* 悪い例：(char) でキャストしてから widening */
uint32_t bad = (char)raw[0] |
               ((uint32_t)(char)raw[1] << 8) |
               ((uint32_t)(char)raw[2] << 16) |
               ((uint32_t)(char)raw[3] << 24);
printf("0x%08x\n", bad);  /* 結果: 0xffffff80 （符号拡張で破損） */

/* よい例：(unsigned char) に通してから widening */
uint32_t good = (unsigned char)raw[0] |
                ((uint32_t)(unsigned char)raw[1] << 8) |
                ((uint32_t)(unsigned char)raw[2] << 16) |
                ((uint32_t)(unsigned char)raw[3] << 24);
printf("0x%08x\n", good);  /* 結果: 0x0000ff80 （正しい） */
```

実測値（悪い例）：`0xffffff80`  
実測値（よい例）：`0x0000ff80`

**差は `0xFF000000` —— 符号拡張で上位 3 バイトが 1 で埋まった。**

## 11.6 部内 CAN 実装に学ぶ

部内のモータードライバ・CAN プロトコル実装（`TEXNITIS_CAN`）では、速度目標値などの `float` を CAN メッセージに詰めます。仕様は「Byte 0 = Port ID、Byte 1-4 = float(LE)、Byte 5-7 = 0 埋め」です。

実装の核となる関数（C++ 原本を C に改変）：

```c
/* float をリトルエンディアンでバイト列に詰める */
void write_float_le(float value, unsigned char data[8], size_t offset) {
    uint32_t u32;
    memcpy(&u32, &value, sizeof(value));  /* ← 型パンなし、memcpy で安全 */

    data[offset + 0] = (unsigned char)(u32 & 0xFF);
    data[offset + 1] = (unsigned char)((u32 >> 8) & 0xFF);
    data[offset + 2] = (unsigned char)((u32 >> 16) & 0xFF);
    data[offset + 3] = (unsigned char)((u32 >> 24) & 0xFF);
}

/* バイト列からリトルエンディアンで float を読む */
float read_float_le(const unsigned char data[8], size_t offset) {
    uint32_t u32 = (unsigned char)data[offset + 0] |
                   ((uint32_t)(unsigned char)data[offset + 1] << 8) |
                   ((uint32_t)(unsigned char)data[offset + 2] << 16) |
                   ((uint32_t)(unsigned char)data[offset + 3] << 24);

    float f;
    memcpy(&f, &u32, sizeof(f));  /* ← 型パンなし、memcpy で安全 */
    return f;
}
```

**この実装が`(unsigned char)` に通す理由：** `data` 配列が `char` で宣言されているため、各要素を読むとき符号拡張のリスクがあります。`(unsigned char)` キャストで確実にゼロ拡張させます。

**`memcpy` を使う理由：** `float` と `uint32_t` は本来無関係な型です。ポインタキャストで型を詐称すると、コンパイラの最適化ルール（厳密エイリアシング）に違反し、予期しない動作を招きます。`memcpy` はバイト列のコピー操作なので、型システムとは独立して安全です。

**往復テスト（部内実装の検証）：**

```c
float original = 3.14f;
unsigned char data[8] = {0};

write_float_le(original, data, 1);
float recovered = read_float_le(data, 1);

if (original == recovered) {
    printf("往復成功\n");
}
```

実測：
```
元の値: 3.14
バイト列: c3 f5 48 40 
復元値: 3.14
→ 往復一致
```

## 手元で試す

以下をコピーしてコンパイル・実行し、自分の環境でも確認してください。

**予想: リトルエンディアンで、`1.0f` のバイト列は `00 00 80 3f` になるはず。**

```c
#include <stdio.h>
#include <stdint.h>
#include <string.h>

void write_uint32_le(uint32_t value, unsigned char out[4]) {
    out[0] = (unsigned char)(value & 0xFF);
    out[1] = (unsigned char)((value >> 8) & 0xFF);
    out[2] = (unsigned char)((value >> 16) & 0xFF);
    out[3] = (unsigned char)((value >> 24) & 0xFF);
}

uint32_t read_uint32_le(const unsigned char data[4]) {
    return (uint32_t)data[0] |
           ((uint32_t)data[1] << 8) |
           ((uint32_t)data[2] << 16) |
           ((uint32_t)data[3] << 24);
}

void write_float_le(float value, unsigned char out[4]) {
    uint32_t u32;
    memcpy(&u32, &value, sizeof(value));
    write_uint32_le(u32, out);
}

float read_float_le(const unsigned char data[4]) {
    uint32_t u32 = read_uint32_le(data);
    float f;
    memcpy(&f, &u32, sizeof(f));
    return f;
}

int main(void) {
    printf("=== エンディアンテスト ===\n");
    uint32_t val = 0x12345678;
    unsigned char bytes[4];
    write_uint32_le(val, bytes);
    printf("0x%08x -> %02x %02x %02x %02x\n", val,
           bytes[0], bytes[1], bytes[2], bytes[3]);

    printf("\n=== float <-> bytes ===\n");
    float f = 1.0f;
    unsigned char fbytes[4];
    write_float_le(f, fbytes);
    printf("%.1f -> %02x %02x %02x %02x\n", f,
           fbytes[0], fbytes[1], fbytes[2], fbytes[3]);

    float recovered = read_float_le(fbytes);
    printf("recovered: %.1f\n", recovered);

    printf("\n=== 符号拡張テスト ===\n");
    unsigned char raw[4] = {0x80, 0xFF, 0x00, 0x00};
    uint32_t u32_good = read_uint32_le(raw);
    printf("バイト列 %02x %02x %02x %02x -> 0x%08x\n",
           raw[0], raw[1], raw[2], raw[3], u32_good);

    return 0;
}
```

実行結果（実測）：

0x12345678 -> 78 56 34 12

=== float <-> bytes ===

## つまずきポイント

### 1. 「バイト列を `*(uint32_t *)&bytes[0]` で読みたい」という誘惑

```c
/* ダメな例 */
uint32_t val = *(uint32_t *)&bytes[0];  /* 厳密エイリアシング違反 */
```

これはコンパイラによっては正常に動くかもしれませんが、最適化レベルを上げると壊れることが多いです。

**診断メッセージ：** コンパイラは違反を報告しないことが多いですが、実行時に予期しない値が出ます。

**修正：** `memcpy` を使う。

```c
uint32_t val;
memcpy(&val, bytes, sizeof(val));  /* 安全 */
```

### 2. `char` の符号性で値が壊れる

```c
char data[8];
/* ... 受信処理で data[0] = 0x80 など ... */

uint32_t bad = (char)data[0] |
               ((uint32_t)(char)data[1] << 8) |
               ...;  /* 符号拡張で上位ビットが 1 で埋まる */
```

**修正：** `(unsigned char)` に通す。

```c
uint32_t good = (unsigned char)data[0] |
                ((uint32_t)(unsigned char)data[1] << 8) |
                ...;  /* ゼロ拡張で上位ビットが 0 */
```

### 3. `float` をバイト列に詰める / 読むときに迷う

「`float` はメモリでどう並んでいるのか」を見たいなら、ポインタキャストではなく `memcpy` で複写し、`uint32_t` として見ます。逆方向も同じ。

```c
float f = 3.14f;
uint32_t u32;
memcpy(&u32, &f, 4);  /* float のメモリ image を uint32_t として得る */
printf("0x%08x\n", u32);
```
