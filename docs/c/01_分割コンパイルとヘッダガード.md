# 1. 分割コンパイルとヘッダガード

> **この章のねらい**: プログラムが大きくなると、1 つの `.c` ファイルではなく複数に分割します。その際に `.h`（ヘッダ）と `.c`（実装）に分ける理由、`#include` の役割、**宣言と定義の違い**をしっかり理解することが重要です。ヘッダガード、`static`（ファイルスコープ）、`extern` といった「目に見えない接続」の仕組みを学ぶことで、チーム開発で見かけるコードが読めるようになります。

## 1.1 なぜ分割するのか — 責任の分離

プログラムが大きくなると、すべてを 1 つの `.c` ファイルに書くのは難しくなります。

**1 ファイル版：**

```c
#include <stdio.h>

int add(int a, int b)
{
  return a + b;
}

int multiply(int a, int b)
{
  return a * b;
}

int main()
{
  printf("add(5, 3) = %d\n", add(5, 3));
  printf("multiply(4, 7) = %d\n", multiply(4, 7));
  return 0;
}
```

これでも動きますが、`add` と `multiply` の実装が `main` と混在しています。

**分割版：** 実装を別ファイルに移します。

```c
// math.h - 宣言だけ
int add(int a, int b);
int multiply(int a, int b);
```

```c
// math.c - 実装
#include "math.h"

int add(int a, int b)
{
  return a + b;
}

int multiply(int a, int b)
{
  return a * b;
}
```

```c
// main.c - 使う側
#include <stdio.h>
#include "math.h"

int main()
{
  printf("add(5, 3) = %d\n", add(5, 3));
  printf("multiply(4, 7) = %d\n", multiply(4, 7));
  return 0;
}
```

`main.c` は `add` と `multiply` の**宣言**を `#include "math.h"` で知ります。
実装は `math.c` にあって、**リンク**の時点で結合されます。

## 1.2 宣言と定義の違い

**宣言（declaration）**
「この関数は存在する」と言うだけで、本体（`{}`）がない。

```c
int add(int a, int b);  // 宣言
```

**定義（definition）**
「この関数の本体はこれ」と実装を書く。

```c
int add(int a, int b)   // 定義
{
  return a + b;
}
```

**大事なポイント：**

- ヘッダ（`.h`）に書くのは**宣言**
- ソースコード（`.c`）に書くのは**定義**
- 同じ関数は複数の `.c` ファイルから宣言されて OK（`#include` で）
- ただし定義は**プログラム全体で 1 つだけ**

宣言が複数あっても大丈夫ですが、定義が 2 つ以上あるとリンク時に「duplicate definition」エラーになります。

## 1.3 `#include` の 2 つの形

**`#include <stdio.h>`**
システムの標準ライブラリを探す。`/usr/include` など標準パスから。

**`#include "math.h"`**
現在のディレクトリ（またはプロジェクトのパス）を探す。

`"` を使うのはプロジェクト内のファイル。`<>` を使うのは外部ライブラリです。

## 1.4 ヘッダガード — 二重 include の防止

ヘッダを `#include` すると、その内容がそこに展開されます。
もし同じヘッダを 2 度 include したら、宣言が 2 回になってしまいます。

```c
#include "math.h"  // 1度目
#include "math.h"  // 2度目 → 同じ宣言が重複
```

これを防ぐのが**ヘッダガード**（header guard）です。

```c
// math.h
#ifndef MATH_H
#define MATH_H

int add(int a, int b);
int multiply(int a, int b);

#endif
```

初回の `#include "math.h"` で、`MATH_H` が定義されます。
2 度目に `#include "math.h"` すると、`MATH_H` は既に定義されているので、`#ifndef MATH_H` の条件は偽となり、中身はスキップされます。

**ヘッダガードの名前は「ファイル名を大文字にして `_H` を付ける」が慣例**。
`config.h` なら `CONFIG_H`、`driver_can.h` なら `DRIVER_CAN_H` です。

## 1.5 `static` — ファイルスコープ（内部リンケージ）

グローバル変数や関数は、通常、どのファイルからでも見えます（外部リンケージ）。
複数ファイルで同じ名前を使うと、リンク時に衝突します。

**問題例：**

```c
// file1.c
int counter = 0;  // 外部リンケージ

int get_count_1(void)
{
  return ++counter;
}
```

```c
// file2.c
int counter = 0;  // 同じ名前 → リンクエラー
```

**解決方法：`static` を付ける**

```c
// file1.c
static int counter = 0;  // ファイルスコープ

int get_count_from_file1(void)
{
  return ++counter;
}
```

```c
// file2.c
static int counter = 0;  // file1 の counter と別の変数

int get_count_from_file2(void)
{
  return ++counter;
}
```

`static` を付けると、その変数はそのファイル内だけで有効になります。
他のファイルから見えなくなるので、名前の衝突が起きません。

**注意：`static` は関数にも使えます。**

```c
// internal.c
static int helper(int x)
{
  return x * 2;
}
```

`static` な関数は、そのファイル内だけで使えます。

## 1.6 `static` — 関数内の static（値が残る）

関数内で `static` 変数を宣言すると、呼び出しを跨いで値が保持されます。

```c
int next_id(void)
{
  static int counter = 100;
  return ++counter;
}
```

初回の呼び出しで `counter` は 100 で初期化されます。
2 回目以降の呼び出しでは、初期化をスキップして、前回の値から始まります。

**つまり：**
- `static int counter = 100;` は「初回だけ実行」
- `return ++counter;` は「毎回実行」

グローバル変数よりも**スコープが狭くて安全**です。

## 1.7 `extern` — 他ファイルの定義を使う

通常、`#include` で宣言を知るので、`extern` は不要です。
ただし、ヘッダガードなしで複数の `.c` ファイルに同じ宣言を書く場合、`extern` で「この変数は別ファイルで定義されている」と明示することもあります。

```c
extern int global_counter;  // 宣言（定義ではない）
```

**`extern` と通常の宣言の違い：**

- `int global_counter;` — グローバルスコープだと「定義」扱い
- `extern int global_counter;` — グローバルスコープでも「宣言だけ」

実装では `#include` を使う方が推奨されます。`extern` の使用は少なくなっています。

## 手元で試す

複数ファイルをコンパイルし、ヘッダガード、`static`、関数内 `static` の動作を確認します。

### 例 1：基本的な分割コンパイル

**予想**: `add(5, 3)` と `multiply(4, 7)` の結果は？

math.h

```c
#ifndef MATH_H
#define MATH_H

int add(int a, int b);
int multiply(int a, int b);

#endif
```

math.c

```c
#include "math.h"

int add(int a, int b)
{
  return a + b;
}

int multiply(int a, int b)
{
  return a * b;
}
```

main.c

```c
#include <stdio.h>
#include "math.h"

int main()
{
  printf("add(5, 3) = %d\n", add(5, 3));
  printf("multiply(4, 7) = %d\n", multiply(4, 7));
  return 0;
}
```

コンパイル：

```bash
gcc -std=c99 -Wall -Wextra -Wpedantic main.c math.c -o multi_file && ./multi_file
```

出力：

<details markdown="1"><summary>解答（実行結果）</summary>

```
add(5, 3) = 8
multiply(4, 7) = 28
```

</details>

### 例 2：関数内の `static`（呼び出しを跨いで値が残る）

**予想**: 呼び出すたびに `counter` は 1, 2, 3 と増えるか。それとも毎回 101 か。

```c
#include <stdio.h>

int next_id(void)
{
  static int counter = 100;
  return ++counter;
}

int main()
{
  printf("next_id() = %d\n", next_id());
  printf("next_id() = %d\n", next_id());
  printf("next_id() = %d\n", next_id());
  return 0;
}
```

コンパイル・実行：

```bash
gcc -std=c99 -Wall -Wextra -Wpedantic -c static_demo.c -o static_demo.o && gcc static_demo.o -o static_demo && ./static_demo
```

出力：

<details markdown="1"><summary>解答（実行結果）</summary>

```
next_id() = 101
next_id() = 102
next_id() = 103
```

</details>

呼び出しを跨いで `counter` の値が保持されています。

### 例 3：ファイルスコープの `static`（別ファイルの同名変数）

**予想**: `file1` と `file2` の `counter` は独立しているか。それとも共有されるか。

file1.c

```c
#include <stdio.h>

static int counter = 0;

int get_count_from_file1(void)
{
  return ++counter;
}
```

file2.c

```c
#include <stdio.h>

static int counter = 1000;

int get_count_from_file2(void)
{
  return ++counter;
}
```

main_static.c

```c
#include <stdio.h>

int get_count_from_file1(void);
int get_count_from_file2(void);

int main()
{
  printf("file1: %d\n", get_count_from_file1());
  printf("file1: %d\n", get_count_from_file1());
  printf("file2: %d\n", get_count_from_file2());
  printf("file2: %d\n", get_count_from_file2());
  return 0;
}
```

コンパイル・実行：

```bash
gcc -std=c99 -Wall -Wextra -Wpedantic main_static.c file1.c file2.c -o static_files && ./static_files
```

出力：

<details markdown="1"><summary>解答（実行結果）</summary>

```
file1: 1
file1: 2
file2: 1001
file2: 1002
```

</details>

2 つの `counter` は完全に独立しています。`static` のおかげで名前の衝突が防がれました。

## つまずきポイント

**`error: conflicting types for 'add'`**
同じ関数に異なる宣言（引数の数や型が違う）があります。
ヘッダの宣言と `.c` ファイルの定義を合わせてください。

**`error: undefined reference to 'add'`**
関数 `add` の定義がみつかりません。
コンパイル時に `.o` ファイルをリンクしてください。
（例：`gcc main.c math.c -o ...` として、`math.c` を含める）

**`error: multiple definition of 'counter'`**
グローバル変数 `counter` が複数ファイルで定義されています。
どちらか一方に `static` を付けるか、片方を削除してください。

**`error: 'math.h' file not found`**
`#include "math.h"` の場所が見つかりません。
ファイルと同じディレクトリにいることを確認するか、パスを合わせてください。

**ヘッダガードの `#define` した名前が衝突する**
ヘッダガードの名前が被らないように注意してください。
1 つのプロジェクトで同じ `#define HEADER_H` を 2 つ以上作らないこと。
