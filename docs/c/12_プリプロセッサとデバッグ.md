# 12. プリプロセッサとデバッグ

> **この章のねらい**: C のプリプロセッサ（マクロ）は、コンパイル前に**単なるテキスト置換**を行います。型チェックも計算もありません。括弧の不足、引数の多重評価、複文マクロの落とし穴を実測で確認します。また `assert` とコンパイル時の型チェック（C11 の `_Static_assert`）を用いて、マイコン制御での堅牢性を高める方法を学びます。

## 12.1 `#define` は文字列置換

**マクロは単なるテキスト置換です。型も検査もありません。**

```c
#define DOUBLE(x) x * 2
```

この場合、`DOUBLE(1 + 2)` は以下のように展開されます。

```c
1 + 2 * 2   // 演算子の優先度により 1 + (2*2) = 5
```

括弧を付けないと、予期しない計算順序になります。

## 12.2 括弧を忘れる罠

**マクロの定義でも、引数でも、括弧が必須です。**

実測で確認すると：

```c
#define DOUBLE_BROKEN(x) x * 2
#define DOUBLE_FIXED(x) ((x) * 2)

DOUBLE_BROKEN(1 + 2)  // 展開：1 + 2 * 2 = 5
DOUBLE_FIXED(1 + 2)   // 展開：((1 + 2) * 2) = 6
```

実測値：

```
DOUBLE_BROKEN(1 + 2) = 5
DOUBLE_FIXED(1 + 2) = 6
```

**括弧を付けるルール：**
- マクロ本体の式全体を括弧で囲む：`((x) * 2)`
- マクロ引数も括弧で囲む：`((x) * (x))`

## 12.3 引数を 2 回評価する罠

**マクロは引数をそのまま複数回代入するため、副作用のある式を渡すと予期しない動作をします。**

```c
#define SQ(x) ((x) * (x))

int i = 0;
int result = SQ(i++);  // i++ が 2 回評価される
```

実測値：

```
SQ(i++)後の i = 2, 結果 = 0
```

**注意：上記は未定義動作です。** `SQ(i++)` は同一式内で `i` を 2 回変更するため、C 標準では「結果は保証されない」とされています。実測ではこの値になりましたが、実行ごと・処理系ごとに異なる可能性があります。

**`SQ(i++)` は書いてはいけません。** 代わりに：

```c
int temp = i;
int result = SQ(temp);
i++;
```

## 12.4 複文マクロは `do { } while (0)` で包む

**複数の文を含むマクロは、`do { ... } while (0)` で包まないと `if` や `else` で壊れます。**

括弧を付けない複文マクロ：

```c
#define LOG_BROKEN(fmt) \
    printf("DEBUG: " fmt "\n"); \
    printf("More info\n")

if (condition)
    LOG_BROKEN("message");  // else が無視される ✗
else
    handle_error();
```

コンパイル時のコンパイラ警告：

```
test_multiline_broken.c:4:5: warning: macro expands to multiple statements [-Wmultistatement-macros]
```

**`do { } while (0)` で修正：**

```c
#define LOG_FIXED(fmt) do { \
    printf("DEBUG: " fmt "\n"); \
    printf("More info\n"); \
} while (0)

if (condition)
    LOG_FIXED("message");  // 正しく制御フローが繋がる ✓
else
    handle_error();
```

セミコロンは呼び出し側で付けます（マクロの末尾には付けない）。

## 12.5 文字列化 `#` とトークン連結 `##`

**`#` は引数を文字列にします。`##` は 2 つのトークンを繋ぎます。**

```c
#define STRINGIFY(x) #x
#define CONCAT(a, b) a ## _ ## b

STRINGIFY(hello)     // "hello"
CONCAT(foo, bar)     // foo_bar（トークン foo と bar を繋ぐ）
```

マクロの展開を確認するには、プリプロセッサの出力を見ます：

```bash
gcc -E -std=c99 myfile.c
```

実測値：

```c
int ((3) + (4));
int foo_bar;
```

## 12.6 `assert` — 実行時の検査とコンパイル時の検査

**`assert(condition)` は、条件が偽なら標準エラーに報告してプログラムを終了させます。**

```c
#include <assert.h>

assert(x > 0);  // x > 0 でなければ、メッセージを出して中止
```

`#define NDEBUG` でアサーションを無効化できます：

```bash
gcc -DNDEBUG myfile.c   // assert が全て消える（条件を評価しない）
```

実測値（展開後の C コード）：

```c
// NDEBUG なし：
assert(1 == 1);

// NDEBUG あり：
((void) (0))   // 何もしない
```

**アサーション内に副作用を書いてはいけません：**

```c
assert(++i == 10);  // NDEBUG 時に ++i が消える ✗

// 正しい：
i++;
assert(i == 10);    // ✓
```

## 12.7 C11 の `_Static_assert` — コンパイル時の型・サイズチェック

**構造体のサイズが変わってはいけない場面（CAN メッセージのペイロードなど）では、コンパイル時に検査します。**

```c
#include <stddef.h>

typedef struct {
    uint32_t timestamp;
    uint8_t data[4];
} CANPayload;

_Static_assert(sizeof(CANPayload) == 8, "CAN payload must be exactly 8 bytes");
```

**`_Static_assert` は C11 からの機能です。** コンパイル時に評価され、条件が偽なら**コンパイルエラー**で止まります。

実行例（失敗時）：

```bash
gcc -std=c11 myfile.c
```

```
test_static_assert_fail.c:8:1: error: static assertion failed: "MyStruct must be 16 bytes"
     8 | _Static_assert(sizeof(MyStruct) == 16, "MyStruct must be 16 bytes");
       | ^~~~~~~~~~~~~~
```

成功時は、何も出力されずコンパイルが通ります：

```c
typedef struct {
    int x;
    char y;
    char padding[3];
} MyStruct;

_Static_assert(sizeof(MyStruct) == 8, "MyStruct must be 8 bytes");
// コンパイル成功、実行結果：sizeof(MyStruct) = 8
```

## 12.8 `-D` でコンパイル時にマクロを定義

**プログラムをコンパイルするときに、コマンドライン引数で `#define` を渡せます。**

```c
#include <stdio.h>

#ifdef DEBUG_MODE
    #define LOG(msg) printf("[DEBUG] %s\n", msg)
#else
    #define LOG(msg)  // 空マクロ（何もしない）
#endif

int main(void) {
    LOG("This is a debug message");
    printf("Program running\n");
    return 0;
}
```

**通常ビルド：**

```bash
gcc -std=c99 -Wall -Wextra -Wpedantic myfile.c -o myfile
./myfile
```

```
Program running
```

**デバッグモードでビルド：**

```bash
gcc -std=c99 -Wall -Wextra -Wpedantic -DDEBUG_MODE myfile.c -o myfile_debug
./myfile_debug
```

```
[DEBUG] This is a debug message
Program running
```

## 12.9 `gcc -E` で展開結果を確認（デバッグ手段）

**マクロが正しく展開されているか、プリプロセッサの出力を見て確認できます。**

```bash
gcc -E -std=c99 myfile.c
```

`-E` フラグはプリプロセッサ段階で止まり、展開済みのコードを標準出力に吐きます。

実測値（抜粋）：

```c
int ((3) + (4));
int foo_bar;
```

マクロが意図した形に展開されているかを見直すのに便利です。

## 手元で試す

プリプロセッサとアサーション、コンパイル時チェックの動作を実際に確認します。

```c
// preprocessor_demo.c
#include <stdio.h>
#include <assert.h>
#include <stddef.h>
#include <stdint.h>

/* 括弧を忘れる罠と引数多重評価 */
#define DOUBLE_BROKEN(x) x * 2
#define DOUBLE_FIXED(x) ((x) * 2)

#define SQ_MACRO(x) ((x) * (x))

/* 複文マクロ */
#define LOG(msg) do { \
    printf("[LOG] %s\n", msg); \
    printf("      (logged)\n"); \
} while (0)

/* CAN メッセージペイロード */
typedef struct {
    uint32_t timestamp;
    uint8_t data[4];
} CANPayload;

_Static_assert(sizeof(CANPayload) == 8, "CANPayload must be exactly 8 bytes");

int main(void)
{
    printf("== Macro expansion pitfalls ==\n");
    printf("DOUBLE_BROKEN(1 + 2) = %d (should be 5, not 6)\n", DOUBLE_BROKEN(1 + 2));
    printf("DOUBLE_FIXED(1 + 2) = %d (should be 6)\n", DOUBLE_FIXED(1 + 2));

    printf("\n== Multi-statement macro ==\n");
    if (1)
        LOG("Hello");
    else
        printf("(never reached)\n");

    printf("\n== assert ==\n");
    assert(1 == 1);
    printf("assert(1 == 1) passed\n");

    printf("\n== sizeof check ==\n");
    printf("sizeof(CANPayload) = %zu (should be 8)\n", sizeof(CANPayload));

    printf("\n== SQ(i++) pitfall (undefined behavior) ==\n");
    int i = 0;
    printf("Before: i = %d\n", i);
    int result = SQ_MACRO(i++);
    printf("After SQ_MACRO(i++): i = %d, result = %d\n", i, result);
    printf("(Note: SQ_MACRO(i++) is undefined behavior; do not use in real code)\n");

    return 0;
}
```

**予想: `DOUBLE_BROKEN(1 + 2)` は 5 になるか（6 ではなく）。括弧を付けると 6 になるか。`_Static_assert` でサイズチェックが通るか。**

```bash
gcc -std=c11 -Wall -Wextra -Wpedantic preprocessor_demo.c -o preprocessor_demo && ./preprocessor_demo
```

<details markdown="1"><summary>解答（実行結果）</summary>

```
== Macro expansion pitfalls ==
DOUBLE_BROKEN(1 + 2) = 5 (should be 5, not 6)
DOUBLE_FIXED(1 + 2) = 6 (should be 6)

== Multi-statement macro ==
[LOG] Hello
      (logged)

== assert ==
assert(1 == 1) passed

== sizeof check ==
sizeof(CANPayload) = 8 (should be 8)

== SQ(i++) pitfall (undefined behavior) ==
Before: i = 0
After SQ_MACRO(i++): i = 2, result = 0
(Note: SQ_MACRO(i++) is undefined behavior; do not use in real code)
```

</details>

以下を確認してください。

<details markdown="1"><summary>解答（答え合わせ）</summary>

1. `DOUBLE_BROKEN(1 + 2)` が 5（6 ではなく）になること。
2. `_Static_assert` がコンパイルを通すこと（`CANPayload` は確かに 8 バイト）。
3. 複文マクロが `if` の中でも正しく動作すること。
4. `SQ_MACRO(i++)` で `i` が 2 になること（未定義動作だが、コンパイラは警告を出す）。

</details>

次に、以下を追加で試してください。

- `-DNDEBUG` でアサーションが消える: `gcc -std=c11 -DNDEBUG preprocessor_demo.c -o preprocessor_demo_ndebug && ./preprocessor_demo_ndebug`
- `-E` で展開を確認: `gcc -E -std=c11 preprocessor_demo.c | head -50`
- `_Static_assert` の失敗例：構造体のサイズが 8 バイトでない場合の、コンパイラエラーメッセージを見る。

## つまずきポイント

**マクロが予期しない形に展開される**

括弧が不足していないか、優先度を確認してください。`gcc -E` で実際の展開形を見てから、マクロを修正します。

**複文マクロの制御フローが壊れる**

`do { ... } while (0)` で包み、セミコロンを呼び出し側で付けてください。

**`assert` 内に副作用を書くと NDEBUG でバグが出る**

アサーション外で副作用を行い、条件判定はアサーション内に限ります。

**`_Static_assert` で既に決まったサイズを超える場合、コンパイルが止まる**

構造体を拡張するときは、`_Static_assert` も一緒に更新してください。

**C99 では `_Static_assert` が使えない**

`-std=c11` または `-std=c17` でコンパイルしてください。または、属性 GNU 拡張の `__attribute__((error()))` などで代用できます。
