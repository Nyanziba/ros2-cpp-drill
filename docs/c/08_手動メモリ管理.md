# 8. 手動メモリ管理

> **この章のねらい**: C ではメモリを手動で確保・解放します。`malloc` は確保に失敗する（`NULL` を返す）可能性があり、`free` 忘れはリークになり、解放後の使用は**落ちずに壊れます**（だから気付けません）。「誰がこのポインタを所有しているか」を常に明確にすることで、バグを減らせます。Address Sanitizer で実際のエラーを見ることで、記憶に残ります。

## 8.1 `malloc` — 動的確保

**`malloc(size)` は `size` バイトを確保し、そのアドレスを返す。失敗時は `NULL`。**

```c
int *p = (int *)malloc(sizeof(int) * 5);
if (p == NULL) {
    fprintf(stderr, "malloc failed\n");
    return 1;
}
```

`malloc` の戻り値は `void *` で、キャストして使います。`sizeof(int) * 5` でサイズを計算。

確保できたら、ポインタを通じて配列のように使えます（`p[0]`、`p[1]`）。
実際に動かした出力は、この章の「手元で試す」にまとめてあります。

**`calloc(count, size)` は初期化付き確保。** メモリを 0 で埋めます。

```c
int *q = (int *)calloc(3, sizeof(int));
if (q == NULL) { /* ... */ }
// q[0], q[1], q[2] は全て 0
```

`calloc` は 0 で埋めることが規格で決まっています。実測は「手元で試す」で確認します。

## 8.2 確保失敗への対応

**`malloc` は常に失敗の可能性を考える。** 組み込みでメモリ不足は起こり得ます。

```c
int *arr = (int *)malloc(sizeof(int) * 1000);
if (arr == NULL) {
    // 確保に失敗した場合の処理
    fprintf(stderr, "Failed to allocate memory\n");
    return -1;
}
// arr を使う...
free(arr);
```

失敗時の処理をスキップすると、`NULL` ポインタの逆参照でクラッシュします。

## 8.3 `free` — 解放

**`free(p)` で `malloc` で確保したメモリを返す。**

```c
int *p = (int *)malloc(sizeof(int));
*p = 42;
printf("*p = %d\n", *p);
free(p);
// p はもう無効
```

`free` したあとの `p` は「もう使ってはいけないアドレスが入っている変数」になります。
値が消えるわけではないので、うっかり使えてしまうのが 8.5 の話です。

**複数の確保・解放。**

```c
int *arr[3];
for (int i = 0; i < 3; i++) {
    arr[i] = (int *)malloc(sizeof(int) * 2);
    arr[i][0] = i * 10;
}
for (int i = 0; i < 3; i++) {
    free(arr[i]);
}
```

**各要素ごとに `free` が必要です。** 配列そのものを 1 回 `free` すれば済む、ということはありません。
実際に動かした出力は「手元で試す」にあります。

## 8.4 メモリリークと二重解放

**リーク：確保したメモリを解放しない。**

```c
void leaky_function(void)
{
    int *p = (int *)malloc(sizeof(int) * 100);
    // ... 処理 ...
    return;  // free 忘れ！メモリリーク
}
```

何度も呼び出されると、メモリが枯渇します。

**二重解放：同じポインタを 2 回 `free` する。**

```c
int *p = (int *)malloc(sizeof(int));
free(p);
free(p);  // 二重解放 → クラッシュ or 定義外の動作
```

## 8.5 解放後使用（Use-After-Free）

**`free` 後、そのポインタを使うと、クラッシュや予期しない値の読み書きが起こる。**

```c
int *p = (int *)malloc(sizeof(int));
*p = 42;
free(p);
printf("*p = %d\n", *p);  // 解放後使用。ここが厄介なところ
```

**期待に反して、これは普通クラッシュしません。** 同じ実行ファイルを 5 回走らせた実測値です。

```
*p = 1599802780     exit=0
*p = -1009684065    exit=0
*p = -1092865557    exit=0
*p = 2119807940     exit=0
*p = 22557486       exit=0
```

毎回違う値が出て、**毎回正常終了します。** これが解放後使用のいちばん危険な性質です。
落ちてくれれば気付けますが、落ちないので気付けません。
テストも通ってしまい、現場で別の値を踏んだときに初めて壊れます。

だから**ツールで見えるようにする**しかありません。
まず `gcc` 自身が気付く場合があります（実測）。

```
warning: pointer ‘p’ used after ‘free’ [-Wuse-after-free]
note: call to ‘free’ here
```

そして Address Sanitizer なら確実に止まります。実際の検出メッセージ：

```
==214035==ERROR: AddressSanitizer: heap-use-after-free on address 0x502000000010
READ of size 4 at 0x502000000010 thread T0
    #0 0x642ec0775345 in main
```

メッセージから、「どこのアドレス」「どのサイズ」「main 関数の何行目」まで特定できます。

## 8.6 所有権の明示

**関数の引数・戻り値のときは、「誰が所有するか」をコメントで明示する。**

```c
// 戻り値のメモリは呼び出し側が free する責任
int *create_array(size_t size)
{
    // ownership: caller must free
    return (int *)malloc(sizeof(int) * size);
}

void process_data(int *data, size_t size)
{
    // ownership: caller owns data, we don't free
    for (size_t i = 0; i < size; i++) {
        printf("%d\n", data[i]);
    }
}
```

「所有権が誰にあるか」を明確にすれば、`free` し忘れ、二重解放、解放後使用を防げます。

## 手元で試す

`malloc`, `calloc`, `free` の動作と、Address Sanitizer でエラーを検出します。

```c
// memory_all.c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    printf("== malloc and free ==\n");
    int *p = (int *)malloc(sizeof(int) * 5);
    if (p == NULL) {
        fprintf(stderr, "malloc failed\n");
        return 1;
    }
    p[0] = 10;
    p[1] = 20;
    printf("p[0] = %d, p[1] = %d\n", p[0], p[1]);
    free(p);

    printf("\n== calloc (zeroed) ==\n");
    int *q = (int *)calloc(3, sizeof(int));
    if (q == NULL) {
        fprintf(stderr, "calloc failed\n");
        return 1;
    }
    printf("q[0] = %d, q[1] = %d, q[2] = %d\n", q[0], q[1], q[2]);
    free(q);

    printf("\n== Multiple allocations ==\n");
    int *arr[3];
    for (int i = 0; i < 3; i++) {
        arr[i] = (int *)malloc(sizeof(int) * 2);
        if (arr[i] == NULL) {
            fprintf(stderr, "malloc failed\n");
            return 1;
        }
        arr[i][0] = i * 10;
        arr[i][1] = i * 100;
    }
    for (int i = 0; i < 3; i++) {
        printf("arr[%d][0] = %d, arr[%d][1] = %d\n", i, arr[i][0], i, arr[i][1]);
        free(arr[i]);
    }

    printf("All cleaned up\n");
    return 0;
}
```

**予想: `calloc` で確保した値は 0 か。複数の `malloc` で異なるアドレスが割り当てられるか。全て `free` できるか。**

```bash
gcc -std=c99 -Wall -Wextra -Wpedantic memory_all.c -o memory_all && ./memory_all
```

<details markdown="1"><summary>解答（実行結果）</summary>

```
== malloc and free ==
p[0] = 10, p[1] = 20

== calloc (zeroed) ==
q[0] = 0, q[1] = 0, q[2] = 0

== Multiple allocations ==
arr[0][0] = 0, arr[0][1] = 0
arr[1][0] = 10, arr[1][1] = 100
arr[2][0] = 20, arr[2][1] = 200
All cleaned up
```

</details>

次に、Address Sanitizer で use-after-free を検出します。

```bash
gcc -std=c99 -Wall -Wextra -Wpedantic -fsanitize=address memory_uaf.c -o memory_uaf && ./memory_uaf
```

コード例（`memory_uaf.c`）：

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *p = (int *)malloc(sizeof(int));
    *p = 42;
    free(p);
    printf("*p = %d\n", *p);  // use-after-free
    return 0;
}
```

Address Sanitizer の出力：

```
==ERROR: AddressSanitizer: heap-use-after-free on address 0x502000000010
READ of size 4 at 0x502000000010 thread T0
    #0 0x... in main

0x502000000010 is located 0 bytes inside of 4-byte region [0x502000000010,0x502000000014)
freed by thread T0 here:
    #0 0x... in free
    #1 0x... in main
```

メモリが解放済みであることが明示されます。

3 点確認してください。

<details markdown="1"><summary>解答（答え合わせ）</summary>

1. `calloc` で確保した値は全て 0。
2. 複数の `malloc` で異なるアドレスが割り当てられる。
3. Address Sanitizer が `free` 済みメモリへのアクセスを検出。

</details>

つぎに以下を試してください。

- `free` 後に `free` をもう一度呼ぶ（二重解放）と何が起こるか
- `malloc` に異常に大きなサイズ（例：`1 << 30`）を渡して、確保失敗を観察

## つまずきポイント

**`malloc` が `NULL` を返す可能性を忘れる**
組み込みシステムではメモリ不足が起こります。常に `NULL` チェックしてください。

**`free` 忘れでメモリリーク**
確保したメモリは責任を持って解放。大量のリークはシステムをハング状態にさせます。

**同じポインタを 2 回 `free` する（二重解放）**
定義外の動作です。ポインタを `NULL` に置き換えるか、フラグで管理してください。

```c
free(p);
p = NULL;   /* これだけでよい */
```

**`free(NULL)` は規格で「何もしない」と決まっています。** だから `p` を `NULL` にしておけば、
うっかりもう一度 `free(p)` してしまっても安全です。`if (p != NULL)` のような
ガードを書く必要はありません。

**解放後も変数が存在しているように見える**
ポインタは単なるアドレスです。`free` は「メモリを返す」だけで、ポインタ変数を消しません。解放後にアクセスしないよう、制御フローを確認してください。

**Address Sanitizer の出力が多い**
ゆっくり読んでください。「どこのアドレス」「malloc/free / どこで確保されたか」が列挙されます。
