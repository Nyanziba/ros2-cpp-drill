# 2. 固定幅整数と暗黙変換

> **この章のねらい**: マイコンでは `uint8_t` や `int16_t` といった「バイト数が固定」な整数型を使います。標準の `int` や `char` は処理系によってサイズが違いますが、固定幅整数は**必ずそのサイズ**です。また、小さい型から大きい型への**汎整数拡張（integer promotion）**と、符号なし型でのオーバーフローの回り込みは、マイコン制御で避けて通れません。この章でしっかり理解しておくと、後の電気制御ドライバ実装での勘違いが減ります。

## 2.1 固定幅整数型 — `uint8_t`, `int16_t`, `uint32_t`

標準 C の `int`, `short`, `long` はサイズが保証されません。

```c
int a = 0;      // サイズ不明（処理系依存）
short b = 0;    // サイズ不明
long c = 0;     // サイズ不明
```

処理系によって 16 ビット、32 ビット、64 ビットになる可能性があります。

**固定幅整数型（C99 以降）**

`<stdint.h>` で定義されている型は、サイズが確実です。

```c
#include <stdint.h>

uint8_t u8 = 255;      // 必ず 1 バイト（0 〜 255）
int16_t s16 = -1000;   // 必ず 2 バイト（-32768 〜 32767）
uint32_t u32 = 4294967295U;  // 必ず 4 バイト（0 〜 4294967295）
int64_t s64 = 9223372036854775807LL;  // 必ず 8 バイト
```

マイコンのレジスタやメモリレイアウトは固定されているので、**固定幅整数型を使う方が安全**です。

## 2.2 符号付きと符号なし

**符号なし型（unsigned）**
0 以上の値のみ。すべてのビットを値に使う。

```c
uint8_t u = 255;  // 最大値
```

**符号付き型（signed）**
負の数も表現できる。最上位ビットが符号を表す（二の補数）。

```c
int8_t s = -1;  // 最小値は -128
```

同じビット数でも、符号なしの方が大きい正の値を表現できます。

| 型 | サイズ | 最小値 | 最大値 |
|---|---|---|---|
| `int8_t` | 1 byte | -128 | 127 |
| `uint8_t` | 1 byte | 0 | 255 |
| `int16_t` | 2 bytes | -32768 | 32767 |
| `uint16_t` | 2 bytes | 0 | 65535 |

## 2.3 汎整数拡張（Integer Promotion）

小さい型の値を使う時、多くの場合**自動的により大きい型に拡張**されます。

```c
uint8_t a = 200;
uint8_t b = 100;
int result = a + b;  // a, b は int に昇格してから足される
```

`a` と `b` は `uint8_t` ですが、加算の前に `int` に拡張されます。
その結果、`result` は 300（正しい値）になります。

**注意：`uint8_t` 同士の演算も拡張される**

```c
uint8_t a = 200;
uint8_t b = 100;
uint8_t c = a + b;  // 300（が int で計算）→ uint8_t に戻すと 44
```

右側で `int` で計算されて 300 になりますが、左側に `uint8_t` に戻すときに、下位 8 ビットだけ抜き出すので 44 になります。

（256 で割った余りが入ります。`300 % 256 = 44`）

## 2.4 オーバーフローと符号なしの回り込み

**符号なし型：定義された動作（回り込み）**

```c
uint8_t u = 255;
u++;  // オーバーフロー
printf("%u\n", u);  // 出力：0
```

255 に 1 を足すと、256 になりますが、`uint8_t` は 255 までなので、**0 に戻ります**（回り込み）。
これは**定義された動作**で、信頼できます。

マイコン制御では、このラップアラウンドを利用してカウンタやタイマーを作ることがあります。

**符号付き型：未定義動作（危険）**

```c
int8_t s = 127;
s++;  // オーバーフロー
printf("%d\n", s);  // 結果は未定義（-128 になることが多いが、保証されない）
```

符号付き型のオーバーフローは**未定義動作**で、コンパイラが何をしてもいいことになっています。
通常は -128 になりますが、それに頼ってはいけません。

## 2.5 `char` の符号性は処理系依存

`char` 型は、符号付きか符号なしかが処理系に任されています。

```c
char c = 255;
if (c > 0) {
  printf("positive\n");  // このパスに行くか、下のパスに行くか不確定
} else {
  printf("negative\n");
}
```

確実に符号を指定したい場合は `signed char` か `unsigned char` を使います。

```c
signed char sc = -1;    // 必ず符号付き
unsigned char uc = 255; // 必ず符号なし
```

マイコンコードでは `uint8_t` や `int8_t` を使うのが推奨される理由がここにあります。

## 2.6 `sizeof` で型のサイズを確認

固定幅整数型は名前通りのサイズが保証されていますが、念のため確認できます。

```c
printf("sizeof(uint8_t) = %zu\n", sizeof(uint8_t));    // 1
printf("sizeof(uint16_t) = %zu\n", sizeof(uint16_t));  // 2
printf("sizeof(uint32_t) = %zu\n", sizeof(uint32_t));  // 4
printf("sizeof(uint64_t) = %zu\n", sizeof(uint64_t));  // 8
```

格式指定子は `%zu`（サイズ型）を使います。

## 手元で試す

固定幅整数型、オーバーフロー、汎整数拡張の動作を確認します。

```c
// ch02_handson.c
#include <stdio.h>
#include <stdint.h>

int main()
{
  printf("== Fixed-width integers and overflow ==\n");

  uint8_t small = 255;
  printf("uint8_t: %u (max)\n", small);
  small++;
  printf("After ++: %u (wrapped to 0)\n", small);

  printf("\n== Integer promotion ==\n");
  uint8_t a = 200;
  uint8_t b = 100;
  printf("a = %u, b = %u\n", a, b);
  printf("a + b = %d (promoted to int)\n", a + b);

  printf("\n== Size of fixed-width types ==\n");
  printf("uint8_t: %zu bytes\n", sizeof(uint8_t));
  printf("uint16_t: %zu bytes\n", sizeof(uint16_t));
  printf("uint32_t: %zu bytes\n", sizeof(uint32_t));
  printf("int8_t: %zu bytes\n", sizeof(int8_t));
  printf("int16_t: %zu bytes\n", sizeof(int16_t));

  printf("\n== Signedness matters ==\n");
  int8_t neg = -1;
  uint8_t uns = 255;
  printf("int8_t(-1) vs uint8_t(255)\n");
  printf("As int: %d vs %d\n", neg, uns);
  printf("Equal? %s\n", neg == (int8_t)uns ? "yes" : "no");

  return 0;
}
```

**予想**: `uint8_t` を increment すると 0 に戻るか。`a + b` の結果は 300 か。`sizeof` は 1, 2, 4 か。

コンパイル・実行：

```bash
gcc -std=c99 -Wall -Wextra -Wpedantic ch02_handson.c -o ch02_handson && ./ch02_handson
```

出力：

<details markdown="1"><summary>解答（実行結果）</summary>

```
== Fixed-width integers and overflow ==
uint8_t: 255 (max)
After ++: 0 (wrapped to 0)

== Integer promotion ==
a = 200, b = 100
a + b = 300 (promoted to int)

== Size of fixed-width types ==
uint8_t: 1 bytes
uint16_t: 2 bytes
uint32_t: 4 bytes
int8_t: 1 bytes
int16_t: 2 bytes

== Signedness matters ==
int8_t(-1) vs uint8_t(255)
As int: -1 vs 255
Equal? yes
```

</details>

`Equal? yes` になる理由に注意してください。`As int:` の行では `-1 vs 255` と
違う値に見えているのに、比較は `neg == (int8_t)uns` で行っています。
`(int8_t)255` が `-1` になるので一致します。

**ただし、範囲外の値を符号付き型へ変換した結果は「処理系定義」です。**
未定義動作ではありませんが、規格が値を決めていないので移植性はありません。
gcc / x86-64 では 2 の補数で折り返して `-1` になりますが、
これに頼ったコードを書かないでください。

3 点確認してください。

<details markdown="1"><summary>解答（答え合わせ）</summary>

1. 255 に 1 を足すと 0 に戻っている（符号なしの回り込み）
2. `a + b` は昇格して計算されるので 300 になっている
3. `sizeof` で確認すると、`uint8_t` は 1 バイト、`uint16_t` は 2 バイトなど、予想通り

</details>

## つまずきポイント

**`error: format '%d' expects argument of type 'int', but argument 2 has type 'uint32_t'`**
固定幅整数型の出力時に格式指定子が違っています。
`uint8_t`, `uint16_t` は `%u`、`int8_t`, `int16_t` は `%d` を使ってください。
C99 では `inttypes.h` の `PRId8`, `PRIu8` などの汎用マクロを使う方法もあります。

**計算結果がおかしい（小さい型同士の演算で値が予想と違う）**
汎整数拡張のせいかもしれません。
`uint8_t x = 255; uint8_t y = x + 1;` で y が 0 でなく 256（またはおかしな値）になっていないか確認してください。

**`uint8_t` でマイナスを代入しても負に見えない**
符号なし型なので、負の値は大きい正の値として解釈されます。
`uint8_t u = -1;` なら `u` は 255 になります。

**オーバーフロー時のコンパイラ警告が出ない**
GCC なら `-Woverflow` を有効にすると警告が出ます。
ただし実際のオーバーフローは実行時に発生するので、動作確認が重要です。
