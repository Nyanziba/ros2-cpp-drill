# 7. ビット演算とレジスタ操作

> **この章のねらい**: マイコン制御では、レジスタの個々のビットを読み書きします。C のビット演算 `&`, `|`, `^`, `~`, `<<`, `>>` を組み合わせ、「1 つのビットを立てる / 落とす / 読む」「他のビットを壊さない」という技法が基本です。部内の CAN プロトコルでは 11-bit ID を `(type << 8) | (device << 4) | cmd` で組み立て、分解するのと同じロジックです。

## 7.1 基本的なビット演算

**OR `|` でビットを立てる。**

```c
uint8_t x = 0;
x |= (1 << 2);    // ビット 2 を立てる
```

`1 << 2` は `0b00000100`（= `0x04`）なので、`x` は `0x04` になります。

| 式 | 2 進 | 16 進 |
| --- | --- | --- |
| `x`（初期値） | `00000000` | `0x00` |
| `1 << 2` | `00000100` | `0x04` |
| `x \|= (1 << 2)` の結果 | `00000100` | `0x04` |

**AND `&` でビットを読む（マスク）。**

```c
int bit2 = (x >> 2) & 1;  // ビット 2 を読む
```

`x` をビット 2 の位置に戻すために `2` 右シフトし、最下位ビットだけを取り出す `& 1`。

**AND + NOT `&= ~()` でビットを落とす（read-modify-write）。**

```c
x &= ~(1 << 2);   // ビット 2 を落とす（他のビットは変えない）
```

ビット 5 が立った状態（`0x24`）から始めると、こうなります。

| 式 | 2 進 | 16 進 |
| --- | --- | --- |
| `x`（ビット 2 と 5 が立っている） | `00100100` | `0x24` |
| `~(1 << 2)` | `11111011` | `0xFB` |
| `x &= ~(1 << 2)` の結果 | `00100000` | `0x20` |

**ビット 5 は残っています。** これが read-modify-write の要点です。

### Read-Modify-Write の重要性

**他のビットを壊さないコツ。**

```c
// 悪い例：ビット 5 を立てたい
x = (1 << 5);  // 他のビットが全て 0 になってしまう ✗

// よい例：ビット 5 だけを立てる
x |= (1 << 5);  // 既存のビット 2 は保持される ✓
```

## 7.2 実例：CAN ID の組み立てと分解

**CAN メッセージは 11-bit ID で宛先とコマンドを示す。**

- bit[10:8] — ReceiverType（受信者カテゴリ）
- bit[7:4] — DeviceId（デバイス番号）
- bit[3:0] — Command（機能コード）

**組み立て：**

```c
uint8_t type = 1;      // ReceiverType::MD = 0x01
uint8_t device = 5;    // デバイス 5
uint8_t cmd = 7;       // コマンド 7

uint16_t can_id = (type << 8) | (device << 4) | cmd;
```

実測値：

```
CAN ID: 0x157 (type=1, device=5, cmd=7)
```

`0x157` の内訳：`0x100`（type, 1 を 8 ビット左シフト）`+ 0x50`（device, 5 を 4 ビット左シフト）`+ 0x7`（cmd）。

**分解：**

```c
uint8_t extracted_type = (can_id >> 8) & 0x07;
uint8_t extracted_device = (can_id >> 4) & 0x0F;
uint8_t extracted_cmd = can_id & 0x0F;
```

実測値：

```
Extracted: type=1, device=5, cmd=7
```

**ビットマスク（`0x07`, `0x0F`）の意味。**

- `0x07` = `0b0111` = 3 ビト分（bit[2:0]）を抽出
- `0x0F` = `0b1111` = 4 ビット分（bit[3:0]）を抽出

右シフトして位置を調整し、必要なビット数だけ取り出す。

## 7.3 XOR `^` でビット反転

**XOR `^` は「同じ値なら 0、異なれば 1」。ビット反転に使える。**

```c
uint8_t x = 0x0F;   // 0b00001111
x ^= 0x03;           // 下位 2 ビットを反転
                     // 0b00001100 = 0x0C
```

XOR は「状態のトグル」に便利です。

```c
#define LED_PIN 3
uint32_t gpio_state = 0;
gpio_state ^= (1 << LED_PIN);  // LED ピンを反転（オン → オフ、オフ → オン）
```

## 7.4 NOT `~` — 注意が必要

**NOT `~` は型全体をビット反転する。**

```c
uint8_t x = 0x01;     // 0b00000001
uint8_t y = ~x;       // 0b11111110 = 0xFF
```

**`~(1 << 2)` でマスクを作る際に注意。** `1` はデフォルトで `int` 型なので、シフト演算で型拡張される可能性があります。

安全に書くなら：

```c
uint8_t x = 0xFF;
x &= ~((uint8_t)(1 << 2));  // 明示的にキャスト
```

## 7.5 符号付きシフトの落とし穴

**右シフト `>>` は、符号付き整数の場合「算術シフト」（符号拡張）になる。**

```c
int8_t neg = -1;   // 0b11111111（全ビット 1）
int8_t shifted = neg >> 1;  // 0b11111111 = -1（符号拡張される）
```

実測値：

```
neg = -1, neg >> 1 = -1 (arithmetic right shift)
```

**符号なし型なら「論理シフト」（0 で埋める）。**

```c
unsigned char uneg = 255;  // 0b11111111
unsigned char ushifted = uneg >> 1;  // 0b01111111 = 127
```

実測値：

```
255u >> 1 = 127 (logical right shift)
```

**ビット操作は常に `unsigned` 型で。** 符号の扱いが不確定になるから。

## 7.6 ビットフィールド — 並び順は処理系依存

**構造体のビットフィールドでも、ビット単位の領域を作れる。**

```c
struct with_bitfield {
    unsigned int a : 3;   // 3 ビット
    unsigned int b : 2;   // 2 ビット
    unsigned int c : 3;   // 3 ビット
} bf;

bf.a = 5;
bf.b = 3;
bf.c = 7;
```

**警告：メモリレイアウトは処理系依存。同じコードでも、GCC と MSVC で順序が異なる可能性がある。**

マイコン制御では、ビットフィールドより**ビット演算を直接使う**ほうが、確実です。

## 手元で試す

ビット操作の基本、CAN ID の組み立て・分解、シフトの動作を実際に確認します。

```c
// bitops_all.c
#include <stdio.h>
#include <stdint.h>

int main(void)
{
    printf("== Basic bit operations ==\n");
    uint8_t x = 0;
    printf("x = 0x%02x\n", x);

    // Set bit 2
    x |= (1 << 2);
    printf("After x |= (1 << 2): x = 0x%02x\n", x);

    // Set bit 5
    x |= (1 << 5);
    printf("After x |= (1 << 5): x = 0x%02x\n", x);

    // Clear bit 2
    x &= ~(1 << 2);
    printf("After x &= ~(1 << 2): x = 0x%02x\n", x);

    // Read bit 5
    int bit5 = (x >> 5) & 1;
    printf("Bit 5 of x: %d\n", bit5);

    printf("\n== CAN ID: (type << 8) | (device << 4) | cmd ==\n");
    uint8_t type = 1;
    uint8_t device = 5;
    uint8_t cmd = 7;
    uint16_t can_id = (type << 8) | (device << 4) | cmd;
    printf("CAN ID: 0x%03x (type=%d, device=%d, cmd=%d)\n", can_id, type, device, cmd);

    // Extract
    uint8_t ext_type = (can_id >> 8) & 0x07;
    uint8_t ext_device = (can_id >> 4) & 0x0F;
    uint8_t ext_cmd = can_id & 0x0F;
    printf("Extracted: type=%d, device=%d, cmd=%d\n", ext_type, ext_device, ext_cmd);

    printf("\n== Signed shift (dangerous) ==\n");
    int8_t neg = -1;
    int8_t shifted = neg >> 1;
    printf("neg = %d, neg >> 1 = %d (arithmetic right shift)\n", neg, shifted);

    unsigned char uneg = 255;
    unsigned char ushifted = uneg >> 1;
    printf("255u >> 1 = %u (logical right shift)\n", ushifted);

    printf("\n== XOR for toggling ==\n");
    uint8_t gpio = 0;
    printf("gpio = 0x%02x\n", gpio);
    gpio ^= (1 << 3);
    printf("After gpio ^= (1 << 3): gpio = 0x%02x\n", gpio);
    gpio ^= (1 << 3);
    printf("After gpio ^= (1 << 3) again: gpio = 0x%02x\n", gpio);

    return 0;
}
```

**予想: CAN ID を組み立てたら `0x157` になるか。分解したら元の値に戻るか。符号付き `int8_t` の右シフトと、符号なし `unsigned char` の右シフトで結果が異なるか。**

```bash
gcc -std=c99 -Wall -Wextra -Wpedantic bitops_all.c -o bitops_all && ./bitops_all
```

```

x = 0x00
After x |= (1 << 2): x = 0x04
After x |= (1 << 5): x = 0x20
After x &= ~(1 << 2): x = 0x20
Bit 5 of x: 1

== CAN ID: (type << 8) | (device << 4) | cmd ==
CAN ID: 0x157 (type=1, device=5, cmd=7)
Extracted: type=1, device=5, cmd=7

== Signed shift (dangerous) ==
neg = -1, neg >> 1 = -1 (arithmetic right shift)
shifted = -1

== XOR for toggling ==
gpio = 0x00
After gpio ^= (1 << 3): gpio = 0x08

```

</details>

3 点確認してください。

<details markdown="1"><summary>解答（答え合わせ）</summary>

1. CAN ID `0x157` を分解すると、`type=1, device=5, cmd=7` に戻ること。
2. 符号付き `int8_t(-1) >> 1` は `-1`（符号拡張）、符号なし `unsigned(255) >> 1` は `127`（0 埋め）。
3. XOR は 2 回実行するとトグル動作（元に戻る）。

</details>

つぎに以下を試してください。

- CAN ID を別のビットパターン（例：`type=6, device=15, cmd=3`）で試す
- `uint8_t` の値に対して `1 << 8` でシフトして、型溢れの動作を観察

## つまずきポイント

**ビット操作の結果が予想と違う**
シフト量、マスク値、型を確認してください。符号拡張の可能性も考慮。

**`x = (1 << bit)` で他のビットが消える**
代入 `=` ではなく、OR 代入 `|=` を使ってください。

**右シフト後の値が負のままになる**
符号付き型で算術シフトされています。`unsigned` 型を使うか、キャストしてください。

**ビットフィールドの順序がプラットフォーム間で異なる**
処理系依存です。マイコン控制では、ビット演算を直接使う方が安全。
