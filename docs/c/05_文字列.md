# 5. 文字列

> **この章のねらい**: C の文字列は「配列 + NUL 終端」という素朴な形式です。NUL 終端がある以上、`strlen` は毎回走査します。`strcpy` は危険で、`strncpy` には落とし穴があります。バッファサイズとどう付き合うか、`snprintf` は何が優れているかを理解することで、バッファオーバーフローを防げます。この章はセキュリティの基本です。

## 5.1 NUL 終端と `strlen`

**C の文字列は「文字の配列 + `'\0'` で終わり」という約束。**

```c
char s[] = "hello";  // メモリレイアウト: 'h', 'e', 'l', 'l', 'o', '\0'
```

`'\0'` は数値 0 を文字として扱ったもので、文字列の終わりを示すマーク（NUL 終端）です。

**`strlen` は NUL を見つけるまで毎回走査する。** 文字列がどこまであるかは、NUL を見つけるまで分かりません。

```c
char s[] = "hello";
size_t len = strlen(s);  // 内部: 'h' 'e' 'l' 'l' 'o' まで数えて 5 を返す
```

実測値：

```
s: hello, strlen(s): 5, sizeof(s): 6
```

`sizeof(s)` は 6 です。理由は「h e l l o NUL」で 6 バイト。`strlen` は NUL を数えず 5 だけを返します。

## 5.2 バッファサイズの数え方

**配列の `sizeof` は「NUL 含めた全バイト」。文字数とは異なる。**

```c
char arr[] = "abc";
printf("sizeof(arr): %zu\n", sizeof(arr));  // 4 (a b c \0)
printf("strlen(arr): %zu\n", strlen(arr));  // 3 (a b c)
```

実測値：

```
sizeof(arr): 4 (includes NUL)
strlen(arr): 3 (without NUL)
```

**バッファに何文字入るか。**

バッファが `char buf[10]` なら、最大 9 文字の他言語文字列を格納できます（最後の 1 バイトは NUL 用）。

## 5.3 `strcpy` の危険

**`strcpy` は宛先バッファのサイズを知らない。危険。**

```c
char buffer[5];
strcpy(buffer, "hello");  // 'h' 'e' 'l' 'l' 'o' '\0' → 6 バイト必要
                           // buffer は 5 バイトだけ → バッファオーバーフロー!
```

コンパイラの警告：

```
warning: '__builtin_memcpy' writing 6 bytes into a region of size 5 overflows the destination
```

`strcpy` は 1990 年代のコードに残っているだけで、新しいコードでは使わないでください。

## 5.4 `strncpy` の罠

**`strncpy` は NUL 終端しない場合がある。** 引数の文字数制限で、NUL を置く余裕がなくなると、NUL なしで終わります。

**未初期化のバッファで試してはいけません。** `buf[4]` に何が入っているかは運任せで、
たまたま 0 だと「NUL が無い」という肝心の点が見えません。**先に既知の値で埋めます。**

```c
#include <stdio.h>
#include <string.h>

int main(void)
{
  /* 16 バイト用意し、前半 10 バイトを 'X' で埋め、11 番目に NUL を置く。
   * こうしておくと「NUL が無いとどこまで読まれるか」が、
   * 配列の外に出ずに観察できます。 */
  char buf[16];
  memset(buf, 'X', 10);
  buf[10] = '\0';

  strncpy(buf, "test", 4);   /* 4 文字だけコピー。NUL を置く余裕を渡していない */

  printf("buf[0..4] = %c %c %c %c %c\n", buf[0], buf[1], buf[2], buf[3], buf[4]);
  printf("buf[4] の数値 = %d   ('X' = 88)\n", (unsigned char)buf[4]);
  printf("strlen(buf) = %zu   ← 4 ではない\n", strlen(buf));
  printf("buf = \"%s\"\n", buf);
  return 0;
}
```

実測値：

```
buf[0..4] = t e s t X
buf[4] の数値 = 88   ('X' = 88)
strlen(buf) = 10   ← 4 ではない
buf = "testXXXXXX"
```

**`strncpy` は 4 文字しかコピーしていないのに、文字列としては 10 文字に見えます。**
NUL を置いていないので、`strlen` も `printf("%s", ...)` も次の NUL まで走り続けるからです。

ここでは自分で 11 番目に NUL を置いておいたので 10 で止まりましたが、
**それが無ければ配列の外まで読みに行きます**（未定義動作）。
バッファオーバーリードは、こうして起きます。

コンパイラも気付いて警告します（実測）。

```
warning: ‘strncpy’ output truncated before terminating nul copying 4 bytes
from a string of the same length [-Wstringop-truncation]
```

**`strncpy` を使うなら、必ず自分で NUL を置く。**

```c
char buf[10];
strncpy(buf, "test", sizeof(buf) - 1);
buf[sizeof(buf) - 1] = '\0';  // 手動で NUL 置き
```

## 5.5 `snprintf` — より安全

**`snprintf` はバッファサイズを引数に取り、自動で NUL 終端する。**

```c
char buf[10];
int written = snprintf(buf, sizeof(buf), "hello world");
printf("snprintf wrote: %d bytes (limited to %zu)\n", written, sizeof(buf));
printf("buf: %s\n", buf);
```

実測値：

```
snprintf wrote: 11 bytes (limited to 10)
buf: hello wor
```

`snprintf` の戻り値は「NUL なしで書きたかった文字数」です。戻り値が `sizeof(buf)` 以上なら、切り詰められたという意味。これで「完全に書けたか」「途中で切れたか」が分かります。

コンパイラ警告：

```
warning: 'hello world' directive output truncated writing 11 bytes into a destination of size 10
```

## 手元で試す

NUL 終端、`strlen` の走査、バッファサイズ、`strcpy`、`strncpy`、`snprintf` を実際に確認します。

```c
// string_all.c
#include <stdio.h>
#include <string.h>

int main(void)
{
  // NUL 終端と sizeof / strlen の違い
  printf("== NUL-terminated string ==\n");
  char s[] = "hello";
  printf("s: %s\n", s);
  printf("strlen(s): %zu, sizeof(s): %zu\n", strlen(s), sizeof(s));

  printf("\n== sizeof vs actual length ==\n");
  char arr[] = "abc";
  printf("sizeof(arr): %zu, strlen(arr): %zu\n", sizeof(arr), strlen(arr));

  // strncpy の罠。未初期化だと運任せになるので 'X' で埋めてから試す
  printf("\n== strncpy doesn't add NUL ==\n");
  char buf1[16];
  memset(buf1, 'X', 10);
  buf1[10] = '\0';
  strncpy(buf1, "test", 4);
  printf("After strncpy(buf1, \"test\", 4):\n");
  printf("  buf1[0]=%c, buf1[1]=%c, buf1[2]=%c, buf1[3]=%c, buf1[4]=%c\n",
         buf1[0], buf1[1], buf1[2], buf1[3], buf1[4]);
  printf("  strlen(buf1)=%zu  buf1=\"%s\"\n", strlen(buf1), buf1);

  // 安全な方法
  printf("\n== Safe: strncpy + manual NUL ==\n");
  char buf2[10];
  strncpy(buf2, "test", sizeof(buf2) - 1);
  buf2[sizeof(buf2) - 1] = '\0';
  printf("buf2: %s\n", buf2);

  // snprintf
  printf("\n== snprintf with size limit ==\n");
  char buf3[10];
  int written = snprintf(buf3, sizeof(buf3), "hello world");
  printf("Written %d bytes (size limit %zu), buf3: %s\n", written, sizeof(buf3), buf3);

  // strlen は毎回走査
  printf("\n== strlen is always linear ==\n");
  char long_str[] = "abcdefghij";
  printf("1st strlen: %zu, 2nd strlen: %zu\n", strlen(long_str), strlen(long_str));

  return 0;
}
```

**予想: `strlen(s)` と `sizeof(s)` の差は何か。`buf1` は NUL 終端しているか。`snprintf` は何バイト書けたか。**

```bash
gcc -std=c99 -Wall -Wextra -Wpedantic string_all.c -o string_all && ./string_all
```

## つまずきポイント

**`error: '__builtin_memcpy' writing N bytes into a region of size M`**
`strcpy` や `strcat` 系でバッファが小さすぎます。`snprintf` を使ってください。

**`strlen(s)` が予期と違う**
文字列が NUL で終わっていない可能性があります。`strncpy` を使った直後なら、NUL を手動で置いてください。

**`strncpy` を使っているのに、`printf("%s", buf)` が異常**
`strncpy` は NUL を置かないことがあります。必ず最後に `buf[size-1] = '\0'` を置いてください。

**`snprintf` の戻り値が負**
フォーマット文字列エラーです。フォーマットを確認してください（通常は戻り値 0 以上）。
