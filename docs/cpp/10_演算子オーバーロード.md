# 10. 演算子オーバーロード

> **この章のねらい**: 前章の最後で「`Point` に `operator<` が無い」というエラーを出し、
> 「`operator<` を定義してください」と書きました。**その定義のしかたを説明していませんでした。**
> この章がそれです。
>
> `operator+` や `operator<` は**ただの関数**です。名前が記号なだけで、特別な文法ではありません。
> それが分かると、`std::sort` が動く条件、`std::cout << x` が動く理由、
> `publisher_->publish(...)` の `->` が何なのか、`qos.reliable().transient_local()` が
> なぜ繋げられるのか、が全部同じ原理で説明できます。

> **前提**: [入門編 6章 `const`](../cpp-basics/06_const.md)の末尾 `const` と、
> [3章 参照](../cpp-basics/03_参照.md)を読んでいる前提です。
> 演算子は関数なので、**引数を `const &` で受けるか、戻り値を参照にするか**の判断が
> そのまま出てきます。

## 10.1 演算子は関数である

まずこれを見てください。

```cpp
#include <iostream>

struct Vec2
{
  double x;
  double y;
};

Vec2 operator+(const Vec2 & a, const Vec2 & b)
{
  return Vec2{a.x + b.x, a.y + b.y};
}

int main()
{
  Vec2 a{1.0, 2.0};
  Vec2 b{10.0, 20.0};

  Vec2 c = a + b;                  // ← operator+(a, b) が呼ばれる
  Vec2 d = operator+(a, b);        // ← まったく同じこと。こう書いてもいい

  std::cout << c.x << "," << c.y << "\n";
  std::cout << d.x << "," << d.y << "\n";
  return 0;
}
```

```
11,22
11,22
```

**`a + b` は `operator+(a, b)` の書き換えにすぎません。**
`operator+` という名前の、ふつうの関数です。
関数なので、宣言・定義・オーバーロード・`const`・参照、全部これまでの章の知識がそのまま効きます。

関数の宣言として読み直してみてください（4 章の右から左の手順）。

```cpp
Vec2 operator+(const Vec2 & a, const Vec2 & b)
//^^^^         ^^^^^^^^^^^^^^  ^^^^^^^^^^^^^^
// 戻り値       a は 変更できない Vec2 への参照（同じく b）
```

- 戻り値は `Vec2`（**値**。参照を返してはいけません。4.3 節のダングリング参照になります）
- 引数は `const Vec2 &`（コピーを避け、書き換えないと約束する）

**この形が演算子オーバーロードの標準形です。** 迷ったらこれを写してください。

## 10.2 メンバとして書くか、自由関数として書くか

同じ `operator+` を、クラスの中に書くこともできます。

```cpp
struct Vec2
{
  double x;
  double y;

  Vec2 operator+(const Vec2 & other) const     // ← メンバ版
  {
    return Vec2{x + other.x, y + other.y};
  }
};
```

**引数が 1 つになりました。** 左辺は `this` だからです。

```cpp
a + b;
// 自由関数版 → operator+(a, b)
// メンバ版   → a.operator+(b)
```

| | 自由関数 | メンバ関数 |
| --- | --- | --- |
| 引数の数（2 項演算子） | 2 個 | 1 個（左辺は `this`） |
| 左辺が自分の型でなくてもよい | **○** | × |
| private メンバに触れる | ×（`friend` が必要） | ○ |
| 末尾 `const` | 不要 | **必要**（左辺を変更しないので） |

### 使い分けの規則

**判断基準は「左辺が自分の型でない場合があるか」です。**

`2.0 * v`（スカラー × ベクトル）を書きたいとします。メンバ版では**不可能**です。
左辺が `double` なので、`double` のメンバ関数として書く必要があり、
`double` は自分で拡張できません。

```cpp
// 自由関数なら書ける
Vec2 operator*(double s, const Vec2 & v)
{
  return Vec2{s * v.x, s * v.y};
}

Vec2 operator*(const Vec2 & v, double s)   // 逆順も別に必要
{
  return Vec2{v.x * s, v.y * s};
}
```

**`v * 2.0` と `2.0 * v` は別の関数です。** 両方欲しければ両方書きます。
片方だけ書いて他方でエラーになるのは、実際によくやる見落としです。

実用的な規則はこうです。

| 演算子 | どちらで書くか |
| --- | --- |
| `+` `-` `*` `/` `==` `!=` `<` `>` `<=` `>=` | **自由関数** |
| `+=` `-=` `*=` `/=` `=` `[]` `()` `->` | **メンバ関数**（言語が要求するものもある） |
| `<<` `>>`（ストリーム） | **自由関数**（左辺が `std::ostream` なので選択肢なし） |

`=` `[]` `()` `->` は**メンバでなければならない**と規格で決まっています。

## 10.3 比較演算子と `std::sort`

前章の宿題です。`std::sort` は何を要求しているのか。

```cpp
#include <algorithm>
#include <vector>

struct Point { int x; int y; };

int main()
{
  std::vector<Point> v{{3, 4}, {1, 2}};
  std::sort(v.begin(), v.end());     // Point に < が無い
  return 0;
}
```

前章で見たとおり、これは 84 行のエラーになり、`grep "error:"` で絞ると 1 行です。

```
error: no match for ‘operator<’ (operand types are ‘Point’ and ‘Point’)
```

**`std::sort` は既定で `a < b` を使って並べます。** だから `operator<` が必要です。

```cpp
bool operator<(const Point & a, const Point & b)
{
  return a.x < b.x;
}
```

これで通ります。戻り値は `bool` です。

### `operator<` は「厳密弱順序」でなければならない

ここが罠です。**`std::sort` に渡す比較は、次の条件を満たさなければなりません。**

1. `a < a` は必ず `false`（自分より小さくない）
2. `a < b` なら `b < a` は `false`
3. `a < b` かつ `b < c` なら `a < c`

これを **厳密弱順序（strict weak ordering）** といいます。
違反すると `std::sort` は**未定義動作**になります。クラッシュすることも実際にあります。

いちばんやりがちな違反はこれです。

```cpp
bool operator<(const Point & a, const Point & b)
{
  return a.x <= b.x;     // ← <= にしてしまった
}
```

`a.x == b.x` のとき `a < b` も `b < a` も `true` になり、条件 2 に違反します。
**`<=` ではなく `<` を書いてください。**

複数のキーで並べたいときは、`std::tie` を使うのが安全で簡単です。

```cpp
#include <tuple>

bool operator<(const Point & a, const Point & b)
{
  return std::tie(a.x, a.y) < std::tie(b.x, b.y);   // x で比較、同値なら y
}
```

`std::tuple` の `operator<` が辞書式比較を正しく実装しているので、
自分で `if` を書くより間違えません。

### `operator==` と `operator!=`

C++17 では**両方書く必要があります。**

```cpp
bool operator==(const Vec2 & a, const Vec2 & b)
{
  return a.x == b.x && a.y == b.y;
}

bool operator!=(const Vec2 & a, const Vec2 & b)
{
  return !(a == b);      // == を使って書く
}
```

`!=` を `==` で実装するのが定石です。**論理を 2 箇所に書かない**ためです。

（C++20 では `auto operator<=>(const Vec2 &) const = default;` と 1 行書けば
6 つの比較演算子が全部生成されます。**ROS 2 Jazzy は C++17 なので使えません。**
将来使えるようになる、ということだけ知っておいてください。）

### 浮動小数の `==` に注意

`Vec2` は `double` を持っています。`operator==` で `a.x == b.x` と書きましたが、
**浮動小数の厳密比較は危険です。**

```cpp
#include <iostream>
int main()
{
  double a = 0.1 + 0.2;
  double b = 0.3;
  std::cout << (a == b) << "\n";
  std::cout << a - b << "\n";
  return 0;
}
```

```
0
5.55112e-17
```

`0.1 + 0.2 != 0.3` です。**2 進小数で 0.1 を正確に表せない**ためです。

テストで浮動小数を比較するときは、gtest の `EXPECT_DOUBLE_EQ`（数 ULP の誤差を許す）や
`EXPECT_NEAR(a, b, tol)` を使います。
課題 11 の解答例が `EXPECT_DOUBLE_EQ` を使っているのはこの理由です。

```cpp
// solutions/11_node_test/test/test_exercise.cpp
EXPECT_DOUBLE_EQ(limit_velocity(5.0, 0.0, 100.0, 1.0), 1.0);
```

## 10.4 `operator<<` — `std::cout` に流せるようにする

`std::cout << x` が動く仕組みも演算子です。

```cpp
#include <iostream>
#include <sstream>

struct Vec2
{
  double x;
  double y;
};

std::ostream & operator<<(std::ostream & os, const Vec2 & v)
{
  os << "(" << v.x << ", " << v.y << ")";
  return os;
}

int main()
{
  Vec2 v{1.5, -2.5};
  std::cout << v << "\n";

  std::ostringstream ss;
  ss << "pos=" << v;
  std::cout << ss.str() << "\n";
  return 0;
}
```

```
(1.5, -2.5)
pos=(1.5, -2.5)
```

**この形は暗記してください。3 つのポイントがあります。**

```cpp
std::ostream & operator<<(std::ostream & os, const Vec2 & v)
//         ^①              ^②                  ^③
```

**① 戻り値は `std::ostream &`（参照）** — これが `<<` を繋げられる理由です。

```cpp
std::cout << v << "\n";
// ((std::cout << v) << "\n")
//  ^^^^^^^^^^^^^^^^ ここが std::ostream & を返すので、続けて << できる
```

**参照を返すのが正しい**唯一のケースです。4.3 節で「参照を返すな」と書きましたが、
`os` は引数として渡された既存のオブジェクトなので、
関数を抜けても死にません。ダングリングになりません。

**② 第 1 引数は `std::ostream &`（非 const）** — 書き込むので `const` にできません。

**③ 第 2 引数は `const Vec2 &`** — 読むだけなのでこれ。

**そして必ず `return os;` を書きます。** 忘れると `<<` を繋げられなくなり、
`error: invalid operands to binary expression` のような分かりにくいエラーになります。

### なぜメンバにできないのか

`std::cout << v` の左辺は `std::cout`、つまり `std::ostream` です。
メンバ関数にするなら `std::ostream` のメンバとして書かなければならず、
**標準ライブラリのクラスに後からメンバを足すことはできません。**

だから自由関数しか選択肢がありません。10.2 節の判断基準そのままです。

### `private` メンバを出したい場合は `friend`

```cpp
class Vec2
{
public:
  Vec2(double x, double y) : x_(x), y_(y) {}

  friend std::ostream & operator<<(std::ostream & os, const Vec2 & v);

private:
  double x_;
  double y_;
};

std::ostream & operator<<(std::ostream & os, const Vec2 & v)
{
  os << "(" << v.x_ << ", " << v.y_ << ")";   // private に触れる
  return os;
}
```

`friend` は「この関数だけは private を見てよい」という許可です。
**`friend` はクラスの中に書きますが、メンバ関数にはなりません。** 自由関数のままです。

`friend` は使いすぎると隠蔽が崩れます。`operator<<` と `operator==` くらいに留めてください。
public なアクセサがあるなら `friend` は不要です。

## 10.5 `+=` とメソッドチェーン

`+=` はメンバとして書きます。

```cpp
struct Vec2
{
  double x;
  double y;

  Vec2 & operator+=(const Vec2 & other)
  {
    x += other.x;
    y += other.y;
    return *this;             // ← 自分自身への参照を返す
  }
};
```

**戻り値が `Vec2 &`（自分への参照）です。** これが 2 つの効果を生みます。

**① 連続して書ける**

```cpp
Vec2 v{0, 0};
v += a += b;      // 動く（あまり書かないが）
```

**② メソッドチェーンができる**

これが実用上重要です。rclcpp の QoS がまさにこの形です。

```cpp
// 課題 12 で書く形
rclcpp::QoS qos(rclcpp::KeepLast(1));
qos.transient_local();
qos.reliable();

// 繋げて書ける（同じ意味）
auto qos = rclcpp::QoS(rclcpp::KeepLast(1)).transient_local().reliable();
```

`transient_local()` が `QoS &` を返しているから `.reliable()` を続けられます。
**演算子ではありませんが、`return *this;` という同じ仕掛けです。**

`+` と `+=` の両方が欲しいときは、`+=` で `+` を実装します。

```cpp
Vec2 operator+(Vec2 a, const Vec2 & b)   // 第1引数を「値」で受けるのがコツ
{
  a += b;         // コピーを書き換える
  return a;       // NRVO が効く（5.4 節）
}
```

第 1 引数をあえて値で受けています。**コピーが 1 個必要なので、
引数として作ってもらったほうがコンパイラが最適化しやすい**という定石です。

## 10.6 やってはいけないこと

演算子オーバーロードは**やりすぎると読めなくなります。**

**規則 1: 記号の意味を変えない。**
`operator+` が引き算をしていたら誰も読めません。
`operator<<` をシフト演算として使うのは正当ですが、
「ログに追記する」のような独自の意味を与えるのは慎重に。

**規則 2: `&&` `||` `,` をオーバーロードしない。**
これらは組み込みでは**短絡評価**します（`a && b` は `a` が false なら `b` を評価しない）。
オーバーロードすると**ただの関数呼び出しになるので、両方評価されます。**
挙動が静かに変わるので、避けてください。

**規則 3: 迷ったら名前付き関数にする。**

```cpp
Vec2 operator^(const Vec2 & a, const Vec2 & b);   // 外積？ XOR？ 分からない
double cross(const Vec2 & a, const Vec2 & b);      // 読める
```

**`cross(a, b)` のほうが良いコードです。**
演算子にすべきなのは「数学記号としての意味が自明なもの」だけです。

**規則 4: オーバーロードできない演算子がある。**
`.` `::` `?:` `sizeof` は不可能です。

## 10.7 ROS 2 のコードに出てくる演算子

自分で書く場面は少ないですが、**読む場面は毎行あります。**

| 式 | 何の演算子か | どこで |
| --- | --- | --- |
| `publisher_->publish(msg)` | `shared_ptr::operator->` | 全課題 |
| `*msg` | `shared_ptr::operator*` | 課題 14 |
| `msg->data` | `unique_ptr::operator->` | 課題 14 |
| `if (auto p = w.lock())` | `shared_ptr::operator bool` | 6 章 |
| `p == nullptr` | `shared_ptr::operator==` | 6 章 |
| `std::cout << x` | `ostream::operator<<` | テスト |
| `v[i]` | `vector::operator[]` | 11 章 |
| `500ms + 1s` | `chrono::duration::operator+` | 12 章 |
| `qos.reliable()` | （演算子ではないが `return *this`） | 課題 12 |

**`operator->` が地味に重要です。** `shared_ptr` は `->` をオーバーロードして
「指す先のメンバにアクセスする」ように見せています。
だから `publisher_->publish(...)` は、`publisher_` が `shared_ptr` であることを
意識せずに書けます。

`operator bool` も便利な仕掛けです。

```cpp
if (auto p = w.lock()) { }      // p が nullptr でなければ true
```

これは `p.operator bool()` が呼ばれています。
`explicit operator bool()` として定義されているので、
`bool b = p;` のような暗黙変換は起きません（2.5 節の `explicit`）。
**`if` の条件の中だけは `explicit` でも変換される**という特別扱いがあります。

## つまずきポイント

**`error: no match for ‘operator<’ (operand types are ‘X’ and ‘X’)`**
`std::sort` / `std::map` / `std::set` に自作型を渡しています。
`operator<` を定義するか、比較関数を渡してください。

**`error: no match for ‘operator*’ (operand types are ‘double’ and ‘Vec2’)`**
`operator*(double, Vec2)` を書いていません。**逆順は別の関数です。**

**`error: passing ‘const Vec2’ as ‘this’ argument discards qualifiers`**
メンバ版の演算子に末尾 `const` を付け忘れています。

```cpp
Vec2 operator+(const Vec2 & other) const   // ← この const
```

**`operator<<` を書いたのに `std::cout << v` が通らない**
3 つ確認してください。

1. 自由関数として書いているか（メンバではダメ）
2. 第 1 引数が `std::ostream &` か
3. `#include <ostream>` または `<iostream>` があるか

**`error: ‘operator<<’ must have exactly one argument`**
メンバ関数として書いています。クラスの外に出してください。

**`<<` が繋がらない**
`return os;` を書き忘れています。または戻り値が `void` になっています。

**`error: ‘operator=’ must be a non-static member function`**
`=` `[]` `()` `->` はメンバ限定です。自由関数にできません。

**`std::sort` がクラッシュする / 結果が変**
`operator<` が厳密弱順序になっていません。`<=` を使っていないか確認してください。
`std::tie` で書き直すと安全です。

**浮動小数の `==` で意図せず false になる**
`0.1 + 0.2 != 0.3` です。10.3 節。テストでは `EXPECT_DOUBLE_EQ` / `EXPECT_NEAR` を使ってください。

## ドリルのどこで出るか

**演算子を「定義する」課題は、C++ 編の cpp10 だけです。**
ROS 2 編の 15 課題では、演算子を定義する必要はありません。

一方 **「使う」場面は全課題にあります。**

| 課題 | 使っている演算子 |
| --- | --- |
| 01 | `publisher_->publish(...)`（`shared_ptr::operator->`）、`"Hello, world! " + std::to_string(...)`（`string::operator+`） |
| 02 | `msg.data.c_str()`（`.` はメンバアクセス。演算子ではない） |
| 04, 05 | `request->a`、`response->sum` |
| 06, 07 | `param.as_int()` などのアクセサ |
| 11 | `EXPECT_DOUBLE_EQ` — 浮動小数を `==` で比較しない理由（10.3 節） |
| 12 | `qos.reliable().transient_local()` — `return *this` によるチェーン |
| 13 | `future.wait_for(2s) != std::future_status::ready`（`enum` の `!=`） |
| 14 | `msg->data`、`*msg`、`p == nullptr` |
| cpp10 | **定義する側。** `+` `-` `*` `==` `!=` `<` `<<` `+=` |

課題 12 の QoS を、この章の目で読み直してみてください。

```cpp
rclcpp::QoS qos(rclcpp::KeepLast(1));
qos.transient_local();
qos.reliable();
```

`transient_local()` と `reliable()` が `QoS &` を返しているので、
**3 行に分けても 1 行に繋げても同じ**です。
`rclcpp::QoS` のヘッダを見ると、実際にこうなっています。

```bash
grep -n "QoS &" /opt/ros/jazzy/include/rclcpp/rclcpp/qos.hpp | head
```

## 対応する課題

この章を読んだら、対応するドリルで手を動かしてください。

- `cpp10_operators` — 演算子をオーバーロードする

```bash
./drill run cpp10
```

課題側からは `./drill read` でこの章に戻ってこられます。
