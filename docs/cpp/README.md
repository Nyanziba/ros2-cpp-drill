# ROS 2 の前に覚える C++（15章）

この講習は、**ROS 2 のドリルに入る前**に読むものです。

rclcpp のコードは、C++ の中でも特定の機能に強く依存しています。
`std::shared_ptr`、ラムダ式、`std::bind`、`std::move`、テンプレート、`std::chrono` のリテラル。
これらを知らないまま `create_publisher<std_msgs::msg::String>("topic", 10)` を読むと、
ROS の概念を学んでいるのか C++ の文法と戦っているのかが分からなくなります。
その状態がいちばん効率が悪いので、先に C++ 側だけを片付けます。

逆に、**C++ の機能を網羅する講習ではありません。**
継承の設計論、自分でテンプレートを書く方法、`constexpr` メタプログラミング、例外安全性の設計。
これらは C++ としては重要でも、このドリルには出てきません。扱いません。

## 何を扱うかは実測で決めました

章立ては「C++ 入門書の目次」ではなく、**このドリルの `exercises/` と `solutions/` を

最後の 2 行がこの講習の性格を決めています。
**テンプレートは「書けるようになる」章ではなく「読めるようになる」章**です。
`create_publisher<T>` を読み下せて、テンプレートのエラーメッセージから当たりを付けられれば十分で、
自分で書く場面はドリル中に一度も来ません。

例外も同じです。ドリル 15 課題に `throw` は 1 つもありません。
それでも 13 章を置いているのは、「なぜ ROS 2 のコードは例外を投げないのか」が
`declare_parameter` の設計や `rclcpp::ok()` の存在理由につながっているからです。

**`override` が 2 箇所しかないのに 3 章を丸ごと継承に充てているのは、
出現数では測れない理由があるからです。**
ドリルの 15 課題すべてが `class X : public rclcpp::Node` で始まります。
`override` を書く機会は少なくても、**継承されたクラスの中でコードを書く**という状況が 100% です。
さらに、ドリルの先にある自律移動のコード（`SimplePlanner`、`SystemInterface` の
プラグイン実装）は純粋仮想関数の実装そのものなので、そこで一気に必要になります。

## 対象

- 他の言語（Python、C、Java、Rust など）でプログラムを書いたことがある
- C++ は「見たことはあるが自分では書いていない」または「学校で少し触った」
- **参照・ポインタ・`const` の読み方は済んでいる前提です。**

**この 15 章は基礎から始めません。** 参照とは何か、ポインタとは何か、`const` が
4 か所で意味を変えること、`static` に 3 つの意味があること — これらは
[入門編（全10章）](../cpp-basics/README.md)が持っています。

| そこが不安なら | 入門編のどこ |
| --- | --- |
| `const int * const p` が読めない | [1章 宣言を読む](../cpp-basics/01_宣言を読む.md) |
| 参照とポインタの区別が付かない | [3章](../cpp-basics/03_参照.md)・[4章](../cpp-basics/04_ポインタ1.md)・[5章](../cpp-basics/05_ポインタ2.md) |
| `const` や `static` で手が止まる | [6章](../cpp-basics/06_const.md)・[7章](../cpp-basics/07_static.md) |

**1〜2 時間で埋まります。** 先に入門編をやったほうが、こちらが速く終わります。

すでに C++ で日常的に書いている方は、**6章（スマートポインタ）と 7章（ラムダと `std::bind`）
だけ**読んで、15章のチェックリストで抜けを確認すれば十分です。

## ROS 2 は要りません

**この 15 章は ROS 2 を一切使いません。**
各章の「手元で試す」は 1 ファイルで完結し、`g++` だけでコンパイルできます。

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic try.cpp -o try && ./try
```

`-std=c++17` は必須です。ROS 2 Jazzy が C++17 を対象にしているため、この講習も C++17 で揃えています。
`-Wall -Wextra -Wpedantic` はドリルの全課題の `CMakeLists.txt` でも有効にしてあるので、
最初から同じ条件で書く癖を付けるために付けています。

掲載しているコードと出力は、すべて手元の g++ 13.3.0 / Ubuntu 24.04 で
実際にコンパイルして確認したものです。

## 進めかた

**上から順に読んでください。** 5章は4章に、6章は5章に依存します。

各章は次の構成です。

- **この章のねらい** — 1 段落。読み飛ばし判断用
- **本文** — 節ごとに「動くコード」→「出力」→「なぜそうなるか」
- **手元で試す** — コピペで動く 1 ファイル。**予想してから実行してください**
- **つまずきポイント** — その機能で実際にやりがちな間違いと、コンパイラが出すメッセージ
- **ドリルのどこで出るか** — 該当する課題番号と、そのファイルの実際の行
- **対応する課題** — この章を読んだあとに解く課題（`./drill run cpp06` の形で出ます）

「手元で試す」は飛ばさないでください。
所有権とムーブは、読んで納得しても書くと間違えます。
**出力を予想してから実行して、外したところが自分の穴です。**

## この講習のあと

15章のチェックリストが埋まったら、ドリルに入ります。

```bash
./drill watch
```

ROS 2 そのものの講習は [ROS 2編](../ros2/01_この記事からスタート_ROS2講習ハブ.md) にあります（全24本）。
ROS 2 側の設計思想は [rclcpp の設計思想](../rclcpp-の設計思想.md) にあります。
**この C++ 講習が「言語の仕組み」、あちらが「ライブラリの設計」**という分担です。
両方が「なぜ戻り値をメンバに持つのか」を扱いますが、
こちらは `weak_ptr` という C++ の機能の側から、あちらは rclcpp のヘッダの実装の側から説明しています。

書き方の規約は [ROS 2 のコーディング規約](../ros2-コーディング規約.md) にあります。
この講習のコードもそれに沿えるよう、ポインタは `char * c`、インデントは空白 2、
波かっこは常に付ける、で書いています。
