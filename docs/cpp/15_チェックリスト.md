# 15. ドリルに入る前のチェックリスト

> **この章のねらい**: 14 章までで習った C++ の機能を、実装の形で確認します。
> 各章のポイントが身についているかを、コードを読んで答える形でチェックします。

## 15.1 コードを読んで答える（10問）

### 問 1: スマートポインタと所有権

```cpp
class MinimalPublisher : public rclcpp::Node {
private:
  rclcpp::Publisher<std_msgs::msg::String>::SharedPtr publisher_;
};

MinimalPublisher::MinimalPublisher() : Node("minimal_publisher") {
  publisher_ = this->create_publisher<std_msgs::msg::String>("topic", 10);
  // 下の方はエラー。なぜ？
}
```

もし上の `publisher_` をメンバ変数ではなく、コンストラクタ内のローカル変数にしたら何が起きますか？

<details markdown="1">
<summary>答え</summary>

`create_publisher()` の戻り値は `shared_ptr` です。ローカル変数にすると、コンストラクタを抜けた瞬間にカウントが 0 になり、Publisher が破棄されます。rclcpp 側は Publisher を `weak_ptr` で持つだけなので、`lock()` は毎回 `nullptr` を返し、Executor は何も実行しません。

**エラーも警告も出ません。** ただ何も publish されません。

詳しくは [6. スマートポインタ](06_スマートポインタ.md) の 6.5 節。

</details>

### 問 2: 継承と public

```cpp
class MinimalPublisher : public rclcpp::Node { ... };
```

この `public` は何を意味していますか？もし `public` を消して `class MinimalPublisher : rclcpp::Node { ... };` と書いたら、何が壊れますか？

<details markdown="1">
<summary>答え</summary>

`public` は「基底クラスの `public` メンバを、派生クラスでも `public` のまま保つ」という意味です。

`public` を消すと **`private` 継承**になり、基底クラスの `public` メンバが派生クラスの `private` になります。すると、外部から `MinimalPublisher` オブジェクトに対して `create_publisher` や `get_logger` を呼べなくなります。ドリルの実装は全部壊れます。

詳しくは [3. 継承](03_継承.md) の 3.1 節と 3.2 節。

</details>

### 問 3: 参照と const の読み方

```cpp
const std::shared_ptr<Request> request
```

この宣言をアルファベットで読んでください。`const` はどこに付いていますか？これは参照ですか？

<details markdown="1">
<summary>答え</summary>

右から左に読みます。

- `request` は
- `shared_ptr<Request>` で
- その `shared_ptr` 自身が **const**

つまり「request は `shared_ptr<Request>` そのもの」で、参照ではありません。参照には `&` が付きます。

もし参照なら `const std::shared_ptr<Request> & request` か `std::shared_ptr<const Request> & request` など、`&` があります。

詳しくは[入門編 1章 宣言を読む](../cpp-basics/01_宣言を読む.md)。

</details>

### 問 4: auto の参照と const

```cpp
const std::vector<std::string> v{"hello", "world"};
const std::string & ref = v[0];

auto a = ref;
auto & b = ref;
const auto & c = ref;
```

`a`, `b`, `c` の型はそれぞれ何ですか？`a = "changed"` は `v[0]` を変えますか？

<details markdown="1">
<summary>答え</summary>

- `a` は `std::string`（参照と const が落ちる）→ **コピー**
- `b` は `const std::string &`（参照が保たれる）
- `c` は `const std::string &`（明示的に const 参照）

`a = "changed"` は `a` **だけ**を変えます。`v[0]` は変わりません。

**`auto` は値として推論し、参照と const を落とします。** 参照が欲しければ自分で `&` を書き足します。

詳しくは [8. auto と型推論](08_autoと型推論.md) の 8.2 節。

</details>

### 問 5: ムーブと所有権

```cpp
auto msg = std::make_unique<std_msgs::msg::String>();
msg->data = "hello";
publisher_->publish(std::move(msg));

std::cout << msg.get();  // msg は今なに？
```

`publish()` のあと、`msg` は何になっていますか？

<details markdown="1">
<summary>答え</summary>

`msg` は `nullptr` です。

`std::move(msg)` は `msg` を右辺値として扱わせ、`publish()` は内部でムーブコンストラクタを呼びます。ムーブされたあと、`unique_ptr` は **必ず `nullptr` になることが規格で保証**されています。

`std::move` は「何も動かさない」。実体は「右辺値として扱う」というキャストです。

詳しくは [5. ムーブと所有権](05_ムーブと所有権.md) の 5.2 節。

</details>

### 問 6: std::bind の 3 つの引数

```cpp
std::bind(&MinimalSubscriber::topic_callback, this, _1)
```

この `&MinimalSubscriber::topic_callback`, `this`, `_1` はそれぞれ何を指していますか？

<details markdown="1">
<summary>答え</summary>

1. `&MinimalSubscriber::topic_callback` — メンバ関数へのポインタ。「&」が必須。
2. `this` — 関数を呼ぶ対象のオブジェクト（`MinimalSubscriber` インスタンス）。
3. `_1` — プレースホルダ。「呼び出し時の 1 番目の引数をここに入れる」という意味。

つまり「MinimalSubscriber の `topic_callback` メンバ関数に、現在のオブジェクト (`this`) と呼び出し時に与える引数 (`_1`) を与える」という意味です。

詳しくは [7. ラムダと std::bind](07_ラムダとstd_bind.md) の 7.2 節。

</details>

### 問 7: 仮想デストラクタ

```cpp
class Base {
public:
  virtual ~Base() {}
};

class Derived : public Base { ... };
```

`virtual ~Base()` がなかったら何が起きますか？

<details markdown="1">
<summary>答え</summary>

`virtual` がないと、基底クラスのポインタ経由で削除するときに **派生クラスのデストラクタが呼ばれません**。リソースリークになります。

```cpp
Base * p = new Derived();
delete p;  // Derived::~Derived() が呼ばれない（virtual がない場合）
```

**基底クラスがデストラクタを持つなら、`virtual` を付けるのが鉄則です。**

ドリルでは `rclcpp::Node` が仮想デストラクタを持つので、`MinimalPublisher` も自動的に安全です。

詳しくは [3. 継承](03_継承.md) の 3.5 節。

</details>

### 問 8: コンパイルエラーとリンクエラー

```
`undefined reference to 'f()'` と `multiple definition of 'f()'` は
どちらがリンクエラーですか？それぞれ何を意味していますか？
```

<details markdown="1">
<summary>答え</summary>

**両方ともリンクエラー**です。コンパイラのメッセージには行番号と抜粋が付きますが、リンカのメッセージには付きません。

- `undefined reference to 'f()'` — **定義が見つからない**。`.cpp` に実装がない、または CMakeLists.txt でリンクされていない。
- `multiple definition of 'f()'` — **複数の翻訳単位に定義がある**。`.hpp` に中身を書いて、`inline` を付け忘れた。

詳しくは [1. ビルドとリンクの仕組み](01_ビルドとリンクの仕組み.md) の 1.5 節。

</details>

### 問 9: ユーザー定義リテラル

```cpp
using namespace std::chrono_literals;

auto delay = 500ms;  // これは有効な C++。なぜ？
```

`500ms` はなぜそのまま書けるのですか？

<details markdown="1">
<summary>答え</summary>

`500ms` は **ユーザー定義リテラル**です。`std::chrono_literals` という名前空間に `operator""ms` という演算子が定義されていて、`using namespace` でそれをグローバルに持ってくるので書けるようになります。

```cpp
// C++ 標準ライブラリの内部
namespace std::chrono_literals {
  constexpr std::chrono::milliseconds operator""ms(unsigned long long count) {
    return std::chrono::milliseconds(count);
  }
}
```

`500ms` は自動的に `std::chrono::milliseconds(500)` に変換されます。

詳しくは [12. chrono と時間](12_chronoと時間.md) の 12.1 節。

</details>

### 問 10: std::sort と operator<

```cpp
struct Point { int x; int y; };

std::vector<Point> v{{3, 4}, {1, 2}};
std::sort(v.begin(), v.end());  // エラー。なぜ？
```

このコードが通らないのは何が足りないからですか？

<details markdown="1">
<summary>答え</summary>

`Point` に **`operator<` が定義されていない**からです。

`std::sort` は要素を比較するために、内部で `a < b` を呼びます。自分で定義した型では、この演算子を用意する必要があります。

```cpp
bool operator<(const Point & a, const Point & b) {
  return a.x < b.x;  // または何か他の比較ロジック
}
```

これを足すと通ります。

詳しくは [10. 演算子オーバーロード](10_演算子オーバーロード.md) の 10.3 節。

</details>

C++ の講習が終わったら、ドリルに入ります。

```bash
./drill list
./drill watch
```

`drill list` は全課題を表示します。C++編（`cpp01`〜`cpp12`）は **10 問の演算子・テンプレート・テストの課題**です。

ROS 2 編（`01`〜`15`）は **15 問のノード・通信・パラメータ・アクションの課題**で、各課題で習った C++ の機能を実装で使います。

**`./drill watch` を実行すると、課題ファイルの変更を監視し、自動でテストを走らせます。** 上から順に進めてください。
