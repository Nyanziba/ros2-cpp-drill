# 11. 標準ライブラリの道具箱

> **この章のねらい**: ドリル全体で **std::string が 33 回、std::vector が 17 回**出てきます。
> この章で扱う「文字列」と「コンテナ」は、ドリル 01〜15 のすべてで使われます。
> さらに std::optional（値があるかもしれない）、std::clamp（値の範囲制限）、enum class（型安全な列挙型）が
> ドリルの中核的な課題で出てきます。
> これらの道具を知らないと、「ROS 2 のコードを読んでいるのか、C++ の API と戦っているのか」が
> 分からなくなります。この章で片付けます。

## 11.1 `std::string` — C++ の文字列

### なぜ `std::string` を使うのか

ROS 2 のメッセージには文字列フィールドがあります。

```cpp
// std_msgs/msg/String.msg
string data
```

C++ で受け取ると `std::string` 型です。

```cpp
// solutions/01_publisher/src/minimal_publisher.cpp
auto message = std_msgs::msg::String();
message.data = "Hello, world! " + std::to_string(count_++);
```

C の `char *` と違い、**`std::string` は長さと メモリ管理を自動で行います。**
バッファオーバーフロー、メモリリークのリスクが激減します。

### `c_str()` — printf スタイル書式に必要なわけ

RCLCPP_INFO は「ロギングマクロ」で、printf のような書式指定を使います。

```cpp
// 実際のドリル 01 のコード
RCLCPP_INFO(this->get_logger(), "Publishing: '%s'", message.data.c_str());
```

**`%s` は `const char *` を期待します。** `std::string` は「クラス」なので、
そのままポインタとして解釈すると、オブジェクトのアドレス（や他の意図しないメモリ）を読んでしまいます。
これは**未定義動作**で、クラッシュするか、ゴミが出るか、運がよければ動きます。

`.c_str()` は `std::string` の中身を `const char *` にして返します。

```cpp
std::string msg = "Hello";
printf("Message: '%s'\n", msg.c_str());  // OK
printf("Message: '%s'\n", msg);          // 未定義動作
```

これはコンパイルエラーではなく、**実行時の罠**です。

### `.size()` と `.empty()`

```cpp
std::string msg = "Hello";
if (!msg.empty()) {
  std::cout << "Length: " << msg.size() << "\n";  // Length: 5
}
```

`.size()` は文字数を返します。`.empty()` は `size() == 0` と同じですが、
読む側にとって「長さの確認」と「内容の有無確認」は意味が異なるので、
明示的に分けられています。

### 文字列の連結と `std::to_string`

`std::string` と `const char *` のリテラルは `+` で連結できます。

```cpp
int count = 42;
std::string greeting = "Count: " + std::to_string(count);
// greeting は "Count: 42"
```

**ただし最初の `+` の左辺は `std::string` でなければなりません。**

```cpp
"Hello" + std::string(" world");  // OK
"Hello" + " world";               // エラー（C 文字列同士の足し算）
```

## 11.2 `std::vector` — 動的配列

### 要素の追加と容量

```cpp
std::vector<int> v;
v.push_back(1);
v.push_back(2);
// v = [1, 2]
```

`.push_back()` は末尾に要素を追加します。
内部で、容量が足りなくなると新しいメモリを確保して**全要素をコピー**します。

多くの要素を追加する場合は、先に `.reserve()` で容量を予約します。

```cpp
std::vector<int> v;
v.reserve(1000);    // 1000 要素分の容量を確保
for (int i = 0; i < 1000; ++i) {
  v.push_back(i);   // この中でメモリ再確保は発生しない
}
```

`.reserve()` は容量を増やすだけで、要素数は増やしません。
実際に要素を入れるには `.push_back()` か `.emplace_back()` を使います。

### `.at()` vs `[]`

```cpp
std::vector<int> v{10, 20, 30};
std::cout << v.at(0);    // 10（範囲チェック有）
std::cout << v[0];       // 10（範囲チェック無）
```

`.at()` は範囲外アクセスで例外 (`std::out_of_range`) を投げます。
`[]` は範囲チェックをしないため、高速ですが、バグが起きると
未定義動作（クラッシュ、ゴミ出力）になります。

ドリルでは範囲が既知なので、通常は `[]` で問題ありません。
しかし不確定な入力を受け取るときは `.at()` を使う価値があります。

### 範囲 for ループ

```cpp
for (auto x : v) { }              // コピーが起きる（8章）
for (auto & x : v) { }            // 書き換え可能な参照
for (const auto & x : v) { }      // 読むだけの参照（推奨）
```

**`const auto &` が既定です。** 書き換えたいときだけ `auto &`、
本当にコピーが欲しいときだけ `auto` にします。

## 11.3 `std::optional<T>` — 値があるかもしれない

返り値が「成功したら値、失敗したら値なし」という場合に使います。

```cpp
// exercises/04_service_server/test/test_exercise.cpp から
std::optional<int64_t> call_add(
  const rclcpp::Node::SharedPtr & server, Probe & probe, int64_t a, int64_t b)
{
  // ... サービス呼び出し ...
  if (!success) {
    return std::nullopt;  // 失敗
  }
  return future.get()->sum;  // 成功時は値を返す
}
```

呼び出し側で`.has_value()` で確認します。

```cpp
auto result = call_add(server, probe, 20, 22);
if (result.has_value()) {
  std::cout << "Sum: " << result.value() << "\n";
} else {
  std::cout << "Failed\n";
}
```

または `*result` で値を取出す（`.has_value()` が `true` であることが前提）。

```cpp
std::cout << "Sum: " << *result << "\n";
```

### sentinel 値との比較

`std::optional` がない時代は、「失敗を示す値」を決めていました。

```cpp
// 古いやり方
int64_t call_add(int64_t a, int64_t b)
{
  if (failed) {
    return -1;      // -1 で「失敗」を示す
  }
  return result;
}
```

しかし `-1` が正当な計算結果のこともあります。
**「失敗したのか、結果が -1 なのか」が区別できません。**

`std::optional` は、その区別を明確に、型で強制します。

```cpp
// 新しいやり方
std::optional<int64_t> call_add(int64_t a, int64_t b)
{
  if (failed) {
    return std::nullopt;  // 値がない
  }
  return result;          // 値がある
}
```

呼び出し側は、`.has_value()` を確認しないとコンパイルエラーになるわけではありませんが、
**「値があるか確認するのか、ないまま使うのか」が呼び出しの側からも明確です。**

`.value_or()` で デフォルト値を指定することもできます。

```cpp
int64_t sum = call_add(server, probe, 10, 20).value_or(-1);
// 成功したら sum、失敗したら -1
```

## 11.4 `std::map` — キーと値のペア

キーから値を素早く引き出せます。

```cpp
std::map<std::string, int> speeds;
speeds["car"] = 100;
speeds["bike"] = 50;
std::cout << speeds["car"] << "\n";  // 100
```

### `operator[]` の罠 — キーが無いと挿入される

`map[key]` でキーが無い場合、**自動的に デフォルト値で新しい要素が作られます。**

```cpp
std::map<std::string, int> config;
int value = config["unknown"];  // キーが無い
// → デフォルト値 0 が挿入される
// → config のサイズが 1 になる
```

「単に確認したい」なら `.find()` か `.count()` を使います。

```cpp
auto it = config.find("unknown");
if (it != config.end()) {
  std::cout << it->second << "\n";
}

if (config.count("unknown")) {
  std::cout << "存在\n";
}
```

### `.at()` — 存在確認付き読み取り

`.at()` で存在しないキーにアクセスすると、例外を投げます。

```cpp
try {
  int value = config.at("unknown");  // キーが無い場合、例外
} catch (const std::out_of_range & e) {
  std::cout << "キーが見つかりません\n";
}
```

## 11.5 `<algorithm>` — 標準的な操作

### `std::max` / `std::min` / `std::clamp`

```cpp
// exercises/11_node_test/src/velocity_limiter.cpp から
const double safe_max_speed = std::max(0.0, max_speed);
const double clamped_delta = std::clamp(delta, -safe_max_delta, safe_max_delta);
```

`std::max(a, b)` は 2 つの値の大きい方、`std::min(a, b)` は小さい方です。

`std::clamp(value, min, max)` は `value` を `[min, max]` の範囲に収めます。
`value < min` なら `min`、`value > max` なら `max`、そうでなければ `value` を返します。

**`std::clamp` は C++17 で追加されました。** ドリルは `-std=c++17` なので問題ありません。

### `std::sort` と `std::find`

```cpp
std::vector<int> nums{3, 1, 4, 1, 5};
std::sort(nums.begin(), nums.end());
// nums = [1, 1, 3, 4, 5]

auto it = std::find(nums.begin(), nums.end(), 4);
if (it != nums.end()) {
  std::cout << "Found at position " << std::distance(nums.begin(), it) << "\n";
}
```

`.begin()` と `.end()` は範囲を指定します。
返されるイテレータが `.end()` なら「見つからなかった」です。

## 11.6 `enum class` — 型安全な列挙型

### 普通の `enum` の問題

```cpp
enum Color {
  RED = 0,
  GREEN = 1,
  BLUE = 2
};

int x = RED;  // 問題ない
```

問題は、`enum` の値が自動的に `int` に変換されることです。

```cpp
enum Status {
  IDLE = 0,
  RUNNING = 1
};

enum Priority {
  LOW = 0,
  HIGH = 1
};

Status s = RUNNING;
Priority p = IDLE;

if (s == p) { }  // バグ！型が全く違う値を比較している
```

さらに、名前がグローバルにバラまかれるので、名前衝突が起きやすい。

### `enum class` による修正

```cpp
enum class Status {
  IDLE,
  RUNNING,
  STOPPED
};

Status s = Status::RUNNING;    // 名前は スコープ付き
// int x = s;                  // エラー：型が違う
int x = static_cast<int>(s);   // 明示的なら可
```

**`enum class` は：**
1. **型安全** — 異なる列挙型同士は比較できない
2. **スコープ付き** — グローバル名前空間を汚さない
3. **暗黙変換なし** — `int` との変換を防ぐ

ドリルでは、ROS 2 の設定オブジェクト（例えば `rclcpp::CallbackGroupType`）が `enum class` で定義されています。
（参考：`exercises/12_qos/test/test_exercise.cpp`）

## 手元で試す

以下のコードでドリルの 01 課題のパターンと、各機能を確認します。

```cpp
// stdlib_toolbox.cpp
#include <iostream>
#include <string>
#include <vector>
#include <optional>
#include <map>
#include <algorithm>

struct Message {
  std::string data;
  int count;

  explicit Message(std::string d, int c) : data(d), count(c) {}
  Message(const Message & o) : data(o.data), count(o.count)
  {
    std::cout << "  [Message copy]\n";
  }
};

std::optional<int> divide(int a, int b)
{
  if (b == 0) {
    return std::nullopt;
  }
  return a / b;
}

int main()
{
  std::cout << "=== std::string ===\n";
  std::string greeting = "Hello";
  greeting = greeting + " world";
  std::cout << "Greeting: '" << greeting << "'\n";
  std::cout << "Size: " << greeting.size() << "\n";
  std::cout << "Empty: " << (greeting.empty() ? "yes" : "no") << "\n";
  printf("Via printf: '%s'\n", greeting.c_str());

  std::cout << "\n=== std::to_string ===\n";
  int count = 42;
  std::string message = "Count: " + std::to_string(count);
  std::cout << message << "\n";

  std::cout << "\n=== std::vector ===\n";
  std::vector<Message> messages;
  messages.reserve(2);
  std::cout << "push_back 1st\n";
  messages.push_back(Message("hello", 0));
  std::cout << "push_back 2nd\n";
  messages.push_back(Message("world", 1));
  std::cout << "Iterating with const auto &\n";
  for (const auto & msg : messages) {
    std::cout << "  msg.data = " << msg.data << ", count = " << msg.count << "\n";
  }

  std::cout << "\n=== std::optional ===\n";
  auto result1 = divide(10, 2);
  std::cout << "divide(10, 2): ";
  if (result1.has_value()) {
    std::cout << *result1 << "\n";
  } else {
    std::cout << "failed\n";
  }
  auto result2 = divide(10, 0);
  std::cout << "divide(10, 0): " << result2.value_or(-1) << "\n";

  std::cout << "\n=== std::map ===\n";
  std::map<std::string, int> speeds;
  speeds["car"] = 100;
  speeds["bike"] = 50;
  std::cout << "car: " << speeds.at("car") << "\n";
  if (speeds.count("plane")) {
    std::cout << "plane: " << speeds["plane"] << "\n";
  } else {
    std::cout << "plane: not found\n";
  }

  std::cout << "\n=== std::algorithm ===\n";
  double value = 15.0;
  double limited = std::clamp(value, 0.0, 10.0);
  std::cout << "clamp(15, 0, 10) = " << limited << "\n";

  std::vector<int> nums{3, 1, 4, 1, 5};
  std::sort(nums.begin(), nums.end());
  std::cout << "Sorted: ";
  for (int n : nums) std::cout << n << " ";
  std::cout << "\n";

  std::cout << "\n=== enum class ===\n";
  enum class Status { IDLE, RUNNING };
  Status s = Status::RUNNING;
  std::cout << "Status: " << static_cast<int>(s) << "\n";

  return 0;
}
```

## つまずきポイント

**`std::string` を printf に直接渡した**

```cpp
std::string msg = "hello";
printf("Message: %s\n", msg);  // 未定義動作
```

```
実行すると予測不能の出力や クラッシュ
```

`.c_str()` を付けてください。

```cpp
printf("Message: %s\n", msg.c_str());
```

**`"hello" + std::string(" world")` がコンパイルエラー**

```cpp
std::string s = "hello" + " world";  // エラー
```

```
error: no match for 'operator+' (operand types are 'const char [6]' and 'const char [7]')
```

左辺を `std::string` にしてください。

```cpp
std::string s = std::string("hello") + " world";
```

**`vector[100]` がクラッシュしなかった**

範囲外アクセスは未定義動作なので、クラッシュするとは限りません。
たまたま有効なメモリを読んでいるか、アドレス空間によっては問題ないかもしれません。
デバッグが困難になるので、確実な範囲アクセスなら `.at()` を使うか、
事前に `.size()` で確認してください。

**`std::map[key]` で意図しない要素が作られた**

```cpp
int v = config["unknown"];  // キーが無ければ、デフォルト値 0 で作成される
if (config.size() > 1) { }  // サイズが増えている
```

読み取り専用なら `.find()` か `.count()` を使ってください。

**`std::optional<int> x; int y = x;` がエラー**

```cpp
std::optional<int> x = 5;
int y = x;  // エラー
```

```
error: cannot convert 'std::optional<int>' to 'int'
```

`.has_value()` で確認するか、`*x` で値を取出すか、`.value_or()` でデフォルト値を指定してください。

**`enum` と `enum class` を混ぜている**

```cpp
enum Color { RED };
enum class Status { RUNNING };

if (RED == Status::RUNNING) { }  // エラー
```

```
error: no match for 'operator==' (operand types are 'Color' and 'Status')
```

列挙型を統一してください。新規コードは `enum class` を使ってください。

## ドリルのどこで出るか

| 課題 | この章の何が出るか |
| --- | --- |
| 01 | `auto message = std_msgs::msg::String(); message.data = "Hello, world! " + std::to_string(count_++);` — std::string の連結と std::to_string |
| 01 | `RCLCPP_INFO(..., "%s", message.data.c_str());` — c_str() が必須 |
| 02 | `const std_msgs::msg::String & msg` — const auto & での受け取り（8章） |
| 04, 05, 13 | `auto future = client_->async_send_request(request);` → `future.wait_for(2s)` で値があるか確認（12章） |
| 11 | `std::max(0.0, max_speed)` と `std::clamp(delta, -safe_max_delta, safe_max_delta)` |
| 11 | `#include <algorithm>` — std::clamp のため |
| 12 | QoS のプロファイル設定（std::map のようなキー・値対） |
| 14 | `ConstSharedPtr msg` で保持（6章） |
| テスト | `std::optional<int64_t> call_add(...)` で返り値の有無を表現（04_service_server/test/test_exercise.cpp） |
| テスト | `std::vector<T>` での要素集約、範囲 for での `const auto &` |
