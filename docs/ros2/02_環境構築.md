# ROS2講習02: 環境構築（Ubuntu 24.04 + ROS 2 Jazzy）

前: [01_この記事からスタート_ROS2講習ハブ](01_この記事からスタート_ROS2講習ハブ.md)

## はじめに

この記事が終わると，自分のPC（またはWSL2）でROS 2 Jazzy Jaliscoが動く状態になり，付属のサンプルノード同士が通信できることまで確認できます。ROS 2はOSへの依存が強いソフトなので，ここでつまずくと以降の講習が全部止まります。焦らず1つずつ確認しながら進めてください。

## 講習目標 / 講習の進め方

- 対象: ROS 2に触るのが初めての新入生
- 前提知識: Linuxの基本的なコマンド操作（`cd`，`ls`，`sudo`など）
- 所要時間: 環境がすでにある人は30分程度，Ubuntuのインストールから行う人は1〜2時間（ダウンロード時間込み）
- 進め方: 本文の手順を上から順に実行し，最後の動作確認まで1人で完走してください。詰まったら「詰まりやすいポイント」を先に見てから，直らなければ先輩に聞きましょう。

## 講習として使う場合

### 準備物

- Ubuntu 24.04のインストールUSB，またはWSL2用のWindows端末（部室PCで対応可能かは事前に確認）
- インターネット接続（apt installで数GB近くダウンロードします。部室のWi-Fiが遅い時間帯は避ける）
- 確認用に自分のPCでも同じ手順を一度通しておくこと。バージョンが上がって手順が変わっていることがあります

### 口頭試問（模範解答つき）

Q1. 新しいターミナルを開いたらいきなり`ros2`コマンドが「command not found」になった。なぜか。

模範解答: `.bashrc`にsourceの追記をしていない，または追記したのに`source ~/.bashrc`していない（新しいターミナルなら自動で読まれるはずなので，追記自体を忘れている可能性が高い）。追記した場所が`.bashrc`ではなく`.bash_profile`など別ファイルだった場合も起こる。

Q2. `talker`は動いているのに，別ターミナルの`listener`にメッセージが届かない。何を疑うか。

模範解答: まず両方のターミナルで`source /opt/ros/jazzy/setup.bash`ができているか確認する。次に`ROS_DOMAIN_ID`が両方のターミナルで同じ値になっているか確認する（片方だけ環境変数を設定していると別ドメインになり通信しない）。ネットワーク的に到達できているか（同じPC内なら基本問題ないが，WSL2やDocker越しだとネットワーク設定が絡む場合がある）も候補に入れる。

Q3. WSL2でROS 2を使うメリットとデメリットを1つずつ挙げよ。

模範解答: メリットはWindows環境を維持しつつLinuxのROS 2が使えること。デメリットはGUIツール（rqt，rviz2，Gazeboなど）の表示が不安定になりやすく，ネットワーク周りの設定でnativeより詰まりやすいこと。

### 時間配分の目安

- Ubuntu環境の用意: 0〜60分（既にある場合は0分，新規インストールなら60分程度）
- ROS 2のインストール: 15分（コマンド自体はコピペで進むが，ダウンロード待ちが発生する）
- 動作確認: 5分
- 詰まった人のフォロー: 状況次第。GPG鍵エラーやWSL2のGUI関連は個別対応が必要になりやすいので，時間を多めに見ておく

## 本文

### 課題1: Ubuntu 24.04を用意する

学習内容：
- ROS 2がOS依存のソフトウェアであること
- native Linux / WSL2 / Dockerそれぞれの向き不向き

準備：
- インストール用USBメモリ，またはWindows端末（WSL2の場合）

内容：

ROS 2 Jazzy Jaliscoの対応OSはUbuntu 24.04（Noble Numbat）です。まず自分の環境を以下の優先順位で用意してください。

1. **Ubuntu 24.04のnative環境（推奨）**。PCにそのままインストールするか，デュアルブートにします。GUIツール（rviz2やGazeboなど）が一番安定して動きます。ロボコンの実機デバッグでは最終的にnativeが必須になる場面が多いので，早いうちに慣れておくのがおすすめです。
2. **WSL2上のUbuntu 24.04（次点）**。Windowsを使い続けたい人向け。コマンドラインでの開発は問題なく進められますが，GUI表示（WSLg）が不安定なことがあります。詳しくは後述の「詰まりやすいポイント」を参照してください。
3. **Docker（macの場合）**。macOSはROS 2を直接インストールできないため，Ubuntu 24.04のDockerコンテナ上で作業します。X11フォワーディングの設定が別途必要になるため，GUIを多用する講習では素直にLinux機を借りるほうが早いこともあります。

ヒント：native環境のインストール自体はUbuntu公式のインストーラに従えば迷うことはありません。パーティション操作が不安な人は先輩に見てもらいましょう。

### 課題2: ROS 2 Jazzyをaptでインストールする

学習内容：
- localeの設定がなぜ必要か
- Ubuntuのuniverseリポジトリとは何か
- apt用のGPG鍵とROS 2の公式リポジトリ登録の仕組み

準備：
- Ubuntu 24.04環境（native/WSL2/Dockerいずれか）が起動していること
- インターネット接続

内容：

公式のDebianパッケージ手順に沿って進めます。ターミナルを開いて，以下を順番に実行してください。

まずlocaleを確認・設定します。ROS 2はUTF-8のlocaleを前提にしているため，ここが崩れているとログ表示などで妙な挙動になります。

```bash
locale  # 確認。LANGやLC_ALL系がUTF-8になっているか見る

sudo apt update && sudo apt install locales
sudo locale-gen en_US en_US.UTF-8
sudo update-locale LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8
export LANG=en_US.UTF-8

locale  # 再確認
```

次にUbuntuのuniverseリポジトリを有効化します。ROS 2のインストールに必要な依存パッケージの一部がここに入っています。

```bash
sudo apt install software-properties-common
sudo add-apt-repository universe
```

続いてROS 2公式のaptリポジトリを登録します。Jazzy以降は`ros2-apt-source`パッケージを使う方式が推奨されているので，これに従います。

```bash
sudo apt update && sudo apt install curl -y

export ROS_APT_SOURCE_VERSION=$(curl -s https://api.github.com/repos/ros-infrastructure/ros-apt-source/releases/latest | grep -F "tag_name" | awk -F\" '{print $4}')
curl -L -o /tmp/ros2-apt-source.deb "https://github.com/ros-infrastructure/ros-apt-source/releases/download/${ROS_APT_SOURCE_VERSION}/ros2-apt-source_${ROS_APT_SOURCE_VERSION}.$(. /etc/os-release && echo $VERSION_CODENAME)_all.deb"
sudo apt install /tmp/ros2-apt-source.deb
```

このパッケージがGPG鍵とaptのソースリストを両方セットアップしてくれます。以前の手順のように鍵を手動で`apt-key`に追加する方式は非推奨になっているので，古い記事やブログの手順は真似しないでください。

最後にパッケージ一覧を更新して，ROS 2本体（Desktop版）をインストールします。

```bash
sudo apt update
sudo apt upgrade  # 既存パッケージとの依存関係の齟齬を防ぐため，ここで上げておく

sudo apt install ros-jazzy-desktop
```

`ros-jazzy-desktop`にはrviz2やturtlesim，デモノード群まで含まれています。ディスク容量は数GB使うので注意してください。開発用のツール（colconなど）が欲しければ以下も入れておきましょう。

```bash
sudo apt install ros-dev-tools
```

ヒント：`apt install`が長時間終わらないように見える時は，回線が細いだけの可能性が高いです。無反応でも数分は待ってから判断してください。

### 課題3: ~/.bashrcにsourceを追記する

学習内容：
- ROS 2の環境変数がシェルのsource方式で読み込まれる仕組み
- overlay/underlayの考え方の前提になる「sourceし忘れると何も使えない」という事実

準備：
- 課題2でros-jazzy-desktopがインストール済みであること

内容：

ROS 2のコマンド（`ros2`）やパッケージのパスは，シェルの環境変数として設定される仕組みになっています。そのため，インストールしただけでは使えません。`/opt/ros/jazzy/setup.bash`を読み込む（source）必要があります。

毎回手打ちするのは非効率なので，`~/.bashrc`に追記して新しいターミナルを開くたびに自動でsourceされるようにします。

```bash
echo "source /opt/ros/jazzy/setup.bash" >> ~/.bashrc
source ~/.bashrc
```

`echo`と`>>`（上書きではなく追記）を使っている点に注意してください。`>`一つだと`.bashrc`の内容が消えます。**心当たりのない`.bashrc`の破壊は絶対にやりたくないので，追記前に`cat ~/.bashrc`で今の内容を確認する癖をつけましょう。**

追記できたか確認するには，新しいターミナルを開いて次を実行します。

```bash
echo $ROS_DISTRO
# jazzy と表示されればOK
```

### 課題4: talker/listenerで動作確認する

学習内容：
- ノード間通信（DDS）が実際に動く様子を目で見る
- 複数ターミナルでのROS 2の基本的な運用感覚

準備：
- 課題3までが完了していること
- ターミナルを2枚開けること（タブでもウィンドウでもよい）

内容：

ROS 2にはデモ用のpub/subノードが標準で入っています。ターミナルを2枚用意して確認しましょう。

1枚目のターミナルで送信側（talker）を起動します。

```bash
ros2 run demo_nodes_cpp talker
```

`Publishing: 'Hello World: 1'`のようなログが1秒おきに流れ始めれば起動成功です。

2枚目のターミナルで受信側（listener）を起動します。

```bash
ros2 run demo_nodes_cpp listener
```

`I heard: [Hello World: 1]`のように，talker側のログと連動した表示が出れば通信成功です。ここまで確認できたら課題4はクリアです。両方のターミナルを`Ctrl+C`で終了してください。

### 課題: talker/listenerが両ターミナルで通ること

これがこの記事のゴールです。上のログが両方のターミナルで問題なく流れていることを確認したら，講師に報告してください。

<details markdown="1"><summary>解答（詰まった場合の確認手順）</summary>

1. 両方のターミナルで`echo $ROS_DISTRO`が`jazzy`と表示されるか確認する（sourceされていない可能性）
2. `ros2 run demo_nodes_cpp talker`がエラーなく起動しているか，1枚目のターミナルのログをよく見る
3. `ros2 topic list`を実行して`/chatter`が出ているか確認する（talkerが動いていれば出るはず）
4. 上記すべて問題なければ`ROS_DOMAIN_ID`が両ターミナルで一致しているか確認する（後述の発展を参照）

</details>

## 詰まりやすいポイント

- **sourceし忘れ**: 一番多いトラブルです。「さっきまで動いていたのに新しいターミナルでは`ros2`が使えない」はほぼこれです。`.bashrc`への追記を再確認してください。
- **GPG鍵エラー**: `ros2-apt-source`パッケージを使わずに古い手順（`apt-key add`など）で鍵を登録すると，Ubuntu 24.04では非推奨警告や失敗が起きます。この記事の手順（`ros2-apt-source_*.deb`をインストールする方式）を使ってください。
- **WSL2のGUI**: rviz2やturtlesimのウィンドウが表示されない，あるいは真っ黒になる場合はWSLgの不具合の可能性があります。Windows側のWSLを最新版に更新する，GPUドライバを更新する，といった対処が必要になることがあります。この講習ではコマンドライン中心なので支障は少ないですが，後続の記事でrqtやrviz2を使う場面で影響してきます。

## 発展

### ROS_DOMAIN_IDの話

`ros2 topic list`や`talker`/`listener`は，デフォルトだと同じネットワーク内の全員が同じ「ドメイン」に属して通信します。つまり，同じ部室のWi-Fiに複数人が同時に`talker`を起動すると，お互いのノードが混線して見えてしまうことがあります。

これを避けるために，`ROS_DOMAIN_ID`という環境変数でドメインを分けられます。

```bash
export ROS_DOMAIN_ID=42  # 0〜101の範囲で好きな番号を選ぶ
```

これを`.bashrc`に書いておけば，自分のPC上で起動するノードは全部このドメイン番号に属するようになり，他のノードと混線しなくなります。値は同じPC・同じロボット上のノード間では揃える必要があるので注意してください。

これは実運用で重要な話です。複数のロボットが同じネットワークにいる状況で，`ROS_DOMAIN_ID`を揃え忘れると通信が混線して予期しない挙動につながります。複数ロボットを運用する場合は，それぞれで異なるドメイン番号を使うか，テストマシンとロボットを分離しておきましょう。
