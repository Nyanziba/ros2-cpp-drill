# ROS2講習07: パラメータ

## はじめに

この記事ではROS2のパラメータを扱います。パラメータはノードの設定値です。この記事を終えると、動いているノードのパラメータを一覧・変更でき、YAMLファイルに書き出して次回起動時に読み込ませられるようになります。

前提として、[04_ノード](04_ノード.md)と[05_トピック](05_トピック.md)を終えていることを前提とします。turtlesimの操作にまだ慣れていない場合は先に[03_turtlesimとrqtで感覚を掴む](03_turtlesimとrqtで感覚を掴む.md)を読んでください。

## 講習目標 / 講習の進め方

- 所要時間: 30分程度
- 対象: 第1部を04まで読み終えた新入生
- 前提知識: `ros2 node`、`ros2 topic` コマンドの基本操作
- ゴール: `ros2 param` 一式（list/get/set/dump/load）を自分で叩き、実行中のノードの設定値を変えられる状態にする

## 講習として使う場合

準備物:
- Ubuntu 24.04 + ROS 2 Jazzy Jalisco がセットアップ済みの端末（[02_環境構築](02_環境構築.md)を完了していること）
- turtlesim パッケージ（`sudo apt install ros-jazzy-turtlesim` で導入済みのはず）
- 端末を2つ以上開ける状態（tmuxでもターミナルタブでもよい）

口頭試問（質問と模範解答）:

1. Q. パラメータとトピックは何が違いますか。ロボコンの機体だとどんな値をパラメータにしますか。
   A. トピックは継続的に流れるデータ（センサ値やcmd_velなど）、パラメータはノードが持つ設定値です。値は明示的に変更されるまで変わりません。ロボコンでは制御ゲイン（Kp/Ki/Kd）、最大速度、ロボットの寸法（ホイール直径、トレッド幅）などをパラメータにします。これらはコードに埋め込むとテストラン現場で調整するたびに再ビルド・再デプロイが必要になり、時間を無駄にします。
2. Q. `ros2 param set` で値を変えたのに、ノードの動作が変わりません。何が起きていますか。
   A. ノード側がパラメータ変更のコールバック（`add_on_set_parameters_callback`など）を実装していない場合、値はパラメータサーバー上では書き換わりますが、ノードの内部変数には反映されません。実行中の変更を実際の動作に反映させるには、ノード側でコールバックを実装して値を読み直す必要があります。この実装は第2部の[15_パラメータとlaunchの実践](15_パラメータとlaunchの実践.md)で扱います。
3. Q. `ros2 param dump` で保存したYAMLを、次回の起動時にどう使いますか。
   A. `ros2 run パッケージ名 実行ファイル名 --ros-args --params-file 保存したYAMLのパス` のように `--params-file` オプションで指定して起動します。launchファイルからも同じYAMLを読み込ませられます（launchでの使い方は09で触れます）。

時間配分の目安:
- 概念説明とコマンドデモ（5分）
- turtlesimでの課題（15分）
- dump/loadの課題と口頭試問（10分）

## 本文

### パラメータとは何か

パラメータは、ノードが起動時に持つ設定値です。トピックのように継続的に流れてくるデータではなく、「PIDのKp」「最大速度」「フレームID」のような、明示的に変更されるまで一定の値を指します。

ROS1では `rosparam` という別コマンドとパラメータサーバーが分離していましたが、ROS2ではパラメータはノードに紐づきます。あるノードのパラメータを見たければ、そのノードを指定してコマンドを叩く必要があります。

### 課題1: パラメータを一覧する

学習内容: `ros2 param list` でノードが持つパラメータを確認する

準備: turtlesimを起動しておきます。

```bash
ros2 run turtlesim turtlesim_node
```

別端末で一覧を取ります。

```bash
ros2 param list
```

`/turtlesim` ノードに紐づくパラメータの一覧が表示されます。`background_r`、`background_g`、`background_b` が背景色のRGB値です。他にも `use_sim_time` など全ノード共通のパラメータが混ざっています。

ヒント: ノードが複数起動している環境では、`ros2 param list /turtlesim` のようにノード名を指定すると絞り込めます。

### 課題2: パラメータの値を取得・変更する

学習内容: `ros2 param get`・`ros2 param set` で値を読み書きする

準備: 課題1のturtlesimを起動したままにします。

内容: 現在の背景色の赤成分を取得します。

```bash
ros2 param get /turtlesim background_r
```

デフォルトは `69` のはずです。これを実行中に変えてみます。

```bash
ros2 param set /turtlesim background_r 255
```

turtlesimのウィンドウを見ると、次に画面が更新されたタイミングで背景の赤みが変わっているはずです（`background_g`、`background_b` も同様に変えられます。全部255にすれば背景が白くなります）。

ヒント: `ros2 param set` は型を自動判定します。数値・文字列・真偽値のいずれでも動きますが、パラメータの型と合わない値を渡すとエラーになります。型を確認したい場合は `ros2 param describe /turtlesim background_r` を使ってください。

練習問題: turtlesimの背景色を紫（R=128, G=0, B=128程度）に変更するコマンドを3つ書いてください。

<details><summary>解答</summary>

```bash
ros2 param set /turtlesim background_r 128
ros2 param set /turtlesim background_g 0
ros2 param set /turtlesim background_b 128
```

</details>

> コラム: なぜロボコンでパラメータ化が重要なのか
>
> 制御ゲインや最大速度をコードにハードコードすると、テストラン現場で「もう少し速く動かしたい」「振動しているのでKpを下げたい」と思ったときに、コードを直して再ビルドして再デプロイする手間が発生します。パラメータ化しておけば `ros2 param set` 一発、あるいはYAML1行の書き換えで済みます。大会前日の現場調整でこの差は大きいです。

### 課題3: パラメータをYAMLに書き出す・読み込む

学習内容: `ros2 param dump`・`--params-file` での永続化

準備: 課題2で背景色を変えた状態のturtlesimを使います。

内容: 現在の全パラメータをYAMLに書き出します。

```bash
ros2 param dump /turtlesim > turtlesim_params.yaml
```

`cat turtlesim_params.yaml` で中身を見てみましょう。ノード名をキーにしたYAML構造で、変更した `background_r` などの値がそのまま反映されています。

一度turtlesimを終了し（Ctrl+C）、保存したYAMLを指定して再起動します。

```bash
ros2 run turtlesim turtlesim_node --ros-args --params-file turtlesim_params.yaml
```

起動直後から背景色が変更後の値になっていることを確認してください。`ros2 param load` というコマンドもありますが、これは起動済みのノードに対してYAMLの内容を反映させるためのもので、起動時に読み込ませたい場合は `--params-file` を使います。

ヒント: `--params-file` はノードが起動時に `declare_parameter` で宣言していないパラメータは無視される場合があります。turtlesimのように事前に宣言済みのパラメータであれば問題なく反映されます。

## 発展（おまけ）

`ros2 param set` で実行中に値を変えても反映されない場合があります。パラメータサーバー上の値は書き換わっていても、ノードの内部で使われる変数がその変更を検知していないと、動作には影響しません。反映させるには、ノード側で `add_on_set_parameters_callback` を使ったコールバックを実装し、変更を受け取って内部状態を更新する処理が必要です。この実装は第2部の[15_パラメータとlaunchの実践](15_パラメータとlaunchの実践.md)で扱います。ここでは「setしても効かないことがある」という事実だけ覚えておいてください。

## おわりに

パラメータはロボコンの機体開発において、コードとチューニング値を分離するための基本手段です。制御ゲインや機体寸法をパラメータ化しておけば、テストラン現場での調整が格段に速くなります。次は[08_アクション](08_アクション.md)に進んでください。わからないところがあれば先輩に聞きましょう。
