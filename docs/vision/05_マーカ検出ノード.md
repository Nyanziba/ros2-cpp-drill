# 5. マーカ検出ノード

- 日本語: https://nyanziba.github.io/ros2-cpp-drill/vision/05_マーカ検出ノード.html
- English: https://nyanziba.github.io/ros2-cpp-drill/en/vision/05_marker_detector_node.html
- 中文: https://nyanziba.github.io/ros2-cpp-drill/zh/vision/05_marker_detector_node.html

検出を関数のままにせず、`image` を購読して `marker` を出すノードにします。試合中の他のノードは、この1行の文字列だけを見ます。遅い検出は「見えた」ではなく `stale` として、古い色で得点しに行かないようにします。

## 文字列

画素規則は cv01 と同じです。`elapsed_ms > budget_ms` のときは、色が見えていても `stale` です。等しいときは stale にしません。それ以外は `red cx cy`、`blue cx cy`、または `none` です。

| 項目 | 決まり |
| --- | --- |
| トピック | 購読 image、出版 marker。QoS は KeepLast(10) の reliable |
| パラメータ | min_pixels の既定は 3、budget_ms の既定は 40 |

## 実カメラとの違い

実カメラは `SensorDataQoS`（best effort）にすることが多いです。この課題のテストは1枚を落とさず届けるので reliable に固定しています。読み物ではその違いを覚えて、ロボットに載せるときに戻してください。

```cpp
format_detection(bgr, min_pixels, elapsed_ms, budget_ms)
// "stale" / "red cx cy" / "blue cx cy" / "none"
```

## CI でやらないこと

カメラドライバは起動しません。テストは同じプロセスの中で青の塊を1枚 publish し、`blue 2 5` が返ることを見ます。

## 対応する課題

```bash
./drill run cv05
```
