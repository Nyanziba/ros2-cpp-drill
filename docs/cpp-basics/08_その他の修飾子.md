# 8. その他の修飾子

> **この章のねらい**: `inline`、`explicit`、`mutable`、`constexpr` は、コンパイラやリンカに対して「こうしてほしい」という指示です。それぞれ全く異なる問題を解きます。`const` や `static` のように覚えておくべき重要な修飾子です。

## 8.1 `inline` — ODR（One Definition Rule）を緩和する

**`inline` は「コンパイラ、この定義は複数の翻訳単位に出てきてもいいよ」という指示です。**

ヘッダファイルに関数の定義を書いて、複数の `.cpp` ファイルから `#include` すると、各翻訳単位で定義が重複します。`inline` なしでリンクすると **multiple definition エラー** になります。

```cpp
// helper.h
int add_one(int x) {
  return x + 1;
}
```

```cpp
// file1.cpp
#include "helper.h"
int get_from_file1() { return add_one(10); }
```

```cpp
// file2.cpp
#include "helper.h"
int get_from_file2() { return add_one(20); }
```

上記をリンクすると：

```
/usr/bin/ld: file2.o: in function `add_one(int)':
file2.cpp:(.text+0x0): multiple definition of `add_one(int)';
file1.o:file1.cpp:(.text+0x0): first defined here
```

**`inline` を付けると、リンカは重複を許可し、1 つに統合します。**

```cpp
// helper.h
inline int add_one(int x) {
  return x + 1;
}
```

これでリンク成功。`nm -C` で確認すると、`inline` なしは `T`（強シンボル）、`inline` は `W`（弱シンボル）：

```
=== Without inline ===
0000000000000000 T add_one(int)

=== With inline ===
0000000000000000 W add_one(int)
```

弱シンボルはリンク時に統合されます。

**モダン C++ では、ヘッダに定義を書くのは `inline` または `constexpr` のいずれかです。**
テンプレートも自動的に `inline` 扱いです。

## 8.2 `explicit` — 暗黙の型変換をブロック

**1 つの引数を取るコンストラクタは、呼び出し側で暗黙に型変換できます。これを防ぐのが `explicit`。**

```cpp
#include <iostream>

class IsEnabled {
public:
  IsEnabled(bool value) : value_(value) {}
  
  bool is_on() const { return value_; }
  
private:
  bool value_;
};

void configure(IsEnabled enabled) {
  if (enabled.is_on()) {
    std::cout << "enabled\n";
  } else {
    std::cout << "disabled\n";
  }
}

int main() {
  configure(true);   // 暗黙に IsEnabled(true) に変換される
  return 0;
}
```

```
enabled
```

これは意図した書き方ですか？ `true` をそのまま渡してしまうと、誤りに気付きません。

**`explicit` を付けると、暗黙変換をブロック。**

```cpp
class IsEnabled {
public:
  explicit IsEnabled(bool value) : value_(value) {}
  
  bool is_on() const { return value_; }
  
private:
  bool value_;
};

// ...
configure(true);  // ERROR
```

```
error: could not convert 'true' from 'bool' to 'IsEnabled'
```

正しい呼び出しは明示的なコンストラクタ呼び出し：

```cpp
configure(IsEnabled(true));   // OK
```

**ROS 2 のコードで `explicit Node(...)` を見かけるのは、この理由です。** ノードのコンストラクタには多くのパラメータを持つバージョンがあり、誤った型を渡されないように保護しています。

## 8.3 `mutable` — `const` メンバ関数からの変更を許可

**`const` メンバ関数では、メンバを変更できません。例外が `mutable`。** `mutable` メンバは、`const` メンバ関数からでも変更できます。

```cpp
#include <iostream>

class CachedValue {
public:
  CachedValue(int value) : value_(value), access_count_(0) {}
  
  int get() const {
    ++access_count_;   // mutable だから const でも変更可能
    return value_;
  }
  
  int access_count() const {
    return access_count_;
  }
  
private:
  int value_;
  mutable int access_count_;
};

int main() {
  const CachedValue cv(42);
  std::cout << cv.get() << "\n";
  std::cout << cv.get() << "\n";
  std::cout << "access count: " << cv.access_count() << "\n";
  return 0;
}
```

```
42
42
access count: 2
```

アクセス回数は、`const` な `get()` の中でもカウントされています。

**正当な使い道：**
- **キャッシュ**：`const` なメンバ関数なのに、キャッシュヒット情報を更新
- **ミューテックス**：マルチスレッドで `const` メンバ関数の実行を保護
- **デバッグカウンター**：呼び出し回数をこっそり記録

**警告：** `mutable` を他の目的で使いたくなったら、**設計を見直してください。** `mutable` は「本来は変わらないはずなのに、実装の都合で変える」という最終手段です。

## 8.4 `constexpr` — コンパイル時計算

**`constexpr` 関数は、コンパイル時に計算できます。** `static_assert` で証明できます（`static_assert` はコンパイル時の式しか受け付けません）。

```cpp
#include <iostream>

constexpr int factorial(int n) {
  return n <= 1 ? 1 : n * factorial(n - 1);
}

// これはコンパイル時に factorial(5) が計算されないと、コンパイルエラー
static_assert(factorial(5) == 120, "factorial must be compile-time");

int main() {
  std::cout << "factorial(5) = " << factorial(5) << "\n";
  return 0;
}
```

```
factorial(5) = 120
```

`static_assert` が通った = **コンパイル時にすべて計算されている。**

**条件：`constexpr` 関数は**
- リテラル型（`int`, `double`, など）を扱う
- 再帰、ループ、分岐 OK
- 実行時にしか分からない入力は受け取らない

C++20 では `constexpr` でできることがさらに増えます（動的メモリ割り当てなど）。

## 手元で試す

4 つの修飾子を 1 つのプログラムで確認します。

```cpp
#include <iostream>

// === inline ===
inline int add_one(int x) {
  return x + 1;
}

// === explicit ===
class IsEnabled {
public:
  explicit IsEnabled(bool value) : value_(value) {}
  
  bool is_on() const { return value_; }
  
private:
  bool value_;
};

void configure(IsEnabled enabled) {
  if (enabled.is_on()) {
    std::cout << "enabled\n";
  } else {
    std::cout << "disabled\n";
  }
}

// === mutable ===
class CachedValue {
public:
  CachedValue(int value) : value_(value), access_count_(0) {}
  
  int get() const {
    ++access_count_;
    return value_;
  }
  
  int access_count() const {
    return access_count_;
  }
  
private:
  int value_;
  mutable int access_count_;
};

// === constexpr ===
constexpr int factorial(int n) {
  return n <= 1 ? 1 : n * factorial(n - 1);
}

static_assert(factorial(5) == 120, "factorial must be compile-time");

int main() {
  std::cout << "=== inline ===\n";
  std::cout << "add_one(10) = " << add_one(10) << "\n";
  
  std::cout << "\n=== explicit ===\n";
  configure(IsEnabled(true));
  configure(IsEnabled(false));
  
  std::cout << "\n=== mutable ===\n";
  const CachedValue cv(42);
  std::cout << "value: " << cv.get() << "\n";
  std::cout << "value: " << cv.get() << "\n";
  std::cout << "access count: " << cv.access_count() << "\n";
  
  std::cout << "\n=== constexpr ===\n";
  std::cout << "factorial(5) = " << factorial(5) << "\n";
  
  return 0;
}
```

**予想: `explicit` で暗黙変換がブロックされるか。`mutable` でアクセスカウンターが増えるか。`static_assert` が通るか。**

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic try.cpp -o try && ./try
```

```
=== inline ===
add_one(10) = 11

=== explicit ===
enabled
disabled

=== mutable ===
value: 42
value: 42
access count: 2

=== constexpr ===
factorial(5) = 120
```

## つまずきポイント

**`error: could not convert 'true' from 'bool' to 'MyClass'`**
コンストラクタに `explicit` を付けました。暗黙変換をブロックするためです。
呼び出し側で明示的に `MyClass(value)` と書いてください。

**`error: assignment of read-only member`**
`mutable` を付け忘れています。`const` メンバ関数の中で変更したいメンバ変数に `mutable` を付けてください。

**`constexpr` 関数がコンパイル時に計算されない**
関数内に、コンパイル時に計算できない操作が含まれています。
例：`std::vector` の使用、ポインタの参照解析など。C++20 の新機能を確認してください。

**`undefined reference to ...`（`inline` 関数がリンカに見つからない）**
`inline` 関数を `.cpp` に定義して、他の `.cpp` から呼び出していないですか？
`inline` や `constexpr` 関数は、定義がヘッダにあるべきです。
