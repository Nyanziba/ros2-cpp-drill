# 10. ヘッダとプロジェクト構成

> **この章のねらい**: C++ では `.h` ファイルと `.cpp` ファイルに分ける理由は、**コンパイラと リンカの作業の分業**です。宣言と定義の違い、翻訳単位、include の動作を理解すると、プロジェクト構成と error メッセージが意味するところが見えてきます。

## 10.1 宣言と定義 — コンパイラとリンカの仕事

**宣言**：「この名前と型の関数/変数が存在する」という情報。**コンパイラが必要。**

**定義**：「その関数/変数の実装は何か」という実体。**コンパイラと リンカ両方が必要。**

```cpp
// 宣言だけ
int add(int a, int b);

// 宣言 + 定義
int add(int a, int b) {
  return a + b;
}
```

**コンパイラは** `add(10, 20)` を呼ぶときに、宣言だけで OK。
**リンカは** その関数の実装を、定義の中に探します。

### 宣言だけでは足りない場合

```cpp
int main() {
  int x = add(10, 20);  // add() は宣言されていない
  return 0;
}
```

[⚠ ブラウザでこのエラーを見る（gcc 13.3）](https://godbolt.org/z/vob5MPqcc)

```
error: 'add' was not declared in this scope
```

**これはコンパイルエラー。** コンパイラが `add()` の宣言を見つけられません。

### 定義だけでは足りない場合

```cpp
// add の宣言
int add(int a, int b);

int main() {
  int x = add(10, 20);  // コンパイル OK
  return 0;
}

// add の定義が存在しない
```

[⚠ ブラウザでこのエラーを見る（gcc 13.3）](https://godbolt.org/z/YhKPa7cMP)

```
/usr/bin/ld: (.text+0x17): undefined reference to `add(int, int)'
```

**これはリンクエラー。** コンパイラは成功しましたが、リンカが定義を見つけられません。

## 10.2 翻訳単位 — 各 `.cpp` は独立してコンパイル

**各 `.cpp` ファイルは独立して、別々にコンパイルされます。** それぞれ `.o`（object）ファイルになり、最後にリンカが 1 つに統合します。

```bash
g++ -c file1.cpp -o file1.o   # ファイル1をコンパイル
g++ -c file2.cpp -o file2.o   # ファイル2をコンパイル
g++ file1.o file2.o main.o    # 3 つをリンク
```

**各翻訳単位内では、その中に書かれた宣言だけが見えます。** 他のファイルの宣言を見たければ、`#include` でヘッダを読み込みます。

例：2 行の `.cpp` に `#include <string>` を書くだけで、プリプロセッサは **25,000 行以上に展開します。**

```bash
echo '#include <string>' > simple.cpp
echo 'int main() { return 0; }' >> simple.cpp
g++ -E simple.cpp | wc -l
```

```
25257
```

`#include` は **テキスト置換。** ヘッダファイルの内容をそっくりそのまま貼り付けます。

## 10.3 多重 include 問題と `#pragma once`

ヘッダを複数のファイルから `#include` すると、同じコンテンツが複数回展開されます。
構造体やクラスの定義が重複すれば、**redefinition エラー** です。

```cpp
// no_guard.h
struct Point {
  int x;
  int y;
};
```

```cpp
// main.cpp
#include "no_guard.h"
#include "no_guard.h"  // 2 回目
int main() { return 0; }
```

```
no_guard.h:1:8: error: redefinition of ‘struct Point’
```

**エラーが指しているのは `no_guard.h` の 1 行目**で、`main.cpp` の
`#include` の行ではありません。`#include` はテキストを貼り付けるので、
コンパイラから見れば問題は貼り付けられた先にあります。
`In file included from ...` の連なりを下から上に読むと、どう辿ってそこに来たかが分かります。

**解決法：`#pragma once`。** ヘッダの最初に書くと、同じファイルが 2 回目に include されるのを防ぎます。

```cpp
// with_pragma_once.h
#pragma once

struct Point {
  int x;
  int y;
};
```

```cpp
// main.cpp
#include "with_pragma_once.h"
#include "with_pragma_once.h"  // 2 回目も OK
int main() {
  Point p = {1, 2};
  (void)p;            // 使わない変数の警告を避けるための決まり文句
  return 0;
}
```

コンパイル成功。`(void)p;` を書かないと `-Wall` で
`warning: unused variable ‘p’` が出ます（ドリルの全課題で `-Wall -Wextra` が有効です）。`#pragma once` はコンパイラに「このファイルは 1 回だけ include する」と指示します。

**昔は `#ifndef` ガードを使っていました。今は `#pragma once` で OK。**

## 10.4 error メッセージの読み方 — コンパイルエラー vs リンクエラー

| error メッセージ | 段階 | 原因 | 対策 |
| --- | --- | --- | --- |
| `error: X was not declared in this scope` | コンパイル | 宣言がない | `.h` に宣言を追加、または `#include` |
| `error: expected ';' before X` | コンパイル | 構文エラー | 文法をチェック |
| `undefined reference to 'X'` | リンク | 定義がない | `.cpp` に定義を追加、または link に含める |
| `multiple definition of 'X'` | リンク | 定義が重複 | 定義が複数の `.cpp` に散らばっている。1 つだけにして、他は `static` か `inline` に |
| `undefined reference to 'ClassName::member'` | リンク | static メンバの定義がない（C++17 未満） | クラス外で定義、または `inline static` に |

## 10.5 最小限の CMake 設定

実際のプロジェクトでは CMake を使用します。

```cmake
cmake_minimum_required(VERSION 3.10)
project(Demo)

set(CMAKE_CXX_STANDARD 17)

# ライブラリを定義（util.cpp から）
add_library(util util.cpp)
target_include_directories(util PUBLIC .)

# 実行ファイルを定義（main.cpp から）
add_executable(demo main.cpp)

# 実行ファイルをライブラリとリンク
target_link_libraries(demo PRIVATE util)
```

**各コマンド：**

- **`add_library(util util.cpp)`**：`util.cpp` から `util` という名前のライブラリを作る
- **`target_include_directories(util PUBLIC .)`**：このライブラリのヘッダは `.` で見つかると CMake に教える
- **`add_executable(demo main.cpp)`**：`main.cpp` から `demo` という実行ファイルを作る
- **`target_link_libraries(demo PRIVATE util)`**：`demo` を `util` ライブラリとリンク

**何が足りないと何が起こるか：**

- `add_library(util util.cpp)` を忘れる → `target_link_libraries` で `util` が見つからない
- `target_include_directories` を忘れる → コンパイルエラー「ヘッダが見つからない」
- `target_link_libraries` を忘れる → リンクエラー「undefined reference」

## 手元で試す

宣言と定義、include ガード、翻訳単位をまとめたプログラムです。

```cpp
#include <iostream>

// === DECLARATION vs DEFINITION ===
// Declaration: tells compiler "this function exists"
// Definition: tells compiler AND linker where the code is

// This is a declaration:
int add(int a, int b);

// This is also a declaration + definition:
int subtract(int a, int b) {
  return a - b;
}

// This is a definition for the declared add():
int add(int a, int b) {
  return a + b;
}

// === HEADER FILE INCLUSION ===
// In a real project, declarations go in .h files and definitions in .cpp files.
// When you #include a .h file, the entire text is pasted at that location.

// === REDEFINITION PROBLEM ===
// If a .h file (without #pragma once) is included twice,
// you get redefinition errors. Solution: use #pragma once or include guards.

int main() {
  std::cout << "=== Declaration vs Definition ===\n";
  std::cout << "add(10, 20) = " << add(10, 20) << "\n";
  std::cout << "subtract(20, 10) = " << subtract(20, 10) << "\n";
  
  std::cout << "\n=== Translation Units ===\n";
  std::cout << "Each .cpp file is compiled independently.\n";
  std::cout << "The linker combines the object files.\n";
  std::cout << "Use 'g++ -c file.cpp' to compile to .o, then link with other .o files.\n";
  
  return 0;
}
```

**予想: コンパイルと実行が成功するか。関数が正しく呼び出されるか。**

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic try.cpp -o try && ./try
```

[▶ ブラウザで実行する（gcc 13.3）](https://godbolt.org/z/Mb6nP5hMh)

```

add(10, 20) = 30
subtract(20, 10) = 10

The linker combines the object files.
Use 'g++ -c file.cpp' to compile to .o, then link with other .o files.
```

## つまずきポイント

**`error: X was not declared in this scope`**
宣言が見つかっていません。ヘッダファイルを `#include` してください。

**`undefined reference to 'X'`**
定義が見つかっていません（リンクエラー）。以下をチェック：
- 定義が `.cpp` に書かれているか
- その `.cpp` が CMakeLists.txt でコンパイル対象か
- `target_link_libraries` で正しくリンクされているか

**`error: redefinition of 'struct X'`**
ヘッダに構造体やクラスの定義があり、複数回 include されています。
ヘッダの先頭に `#pragma once` を追加してください。

**CMake でライブラリが見つからない**
- `add_library(...)` で定義されているか確認
- `target_link_libraries(...)` で指定されているか確認
- タイプミスがないか確認

**ヘッダに関数の実装を書いてもいい場合**
- テンプレート
- `constexpr` 関数
- `inline` 関数
- メンバ関数（クラス内定義）

それ以外は複数定義になるため、`inline` を付けるか、`.cpp` に移してください。
