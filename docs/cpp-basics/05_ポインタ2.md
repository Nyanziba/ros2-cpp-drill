# 5. ポインタ②（配列と使い分け）

> **この章のねらい**: ポインタの威力は配列走査にあります。`int arr[10]` という配列と、`int * p = arr;` というポインタは密接に関係しています。
> この章では、配列からポインタへの自動変換、ポインタ演算の意味、そして参照とポインタの使い分けを学びます。
> モダン C++ では生ポインタを直接使う場面は限定的ですが、既存コードを読むには必須です。

## 5.1 配列からポインタへの自動変換（decay）

配列名を値として使うと、自動的に最初の要素へのポインタに変換されます。
これを**配列からポインタへの decay（衰退）**と言います。

```cpp
int arr[3]{10, 20, 30};
int * p = arr;          // arr は自動的に &arr[0] に変換される

std::cout << arr;       // アドレス（decay した結果）
std::cout << &arr[0];   // 同じアドレス
```

**ただし、`sizeof` は異なります：**

```cpp
sizeof(arr);    // 12 bytes（配列全体：3 × 4）
sizeof(p);      // 8 bytes（ポインタそのもの）
```

## 5.2 ポインタ演算

ポインタに整数を加減すると、そのバイト数だけではなく、**指す型のサイズだけ進みます。**

```cpp
int arr[4]{100, 200, 300, 400};
int * p = &arr[0];

p + 0   // アドレスはそのまま、*p = 100
p + 1   // アドレス + 4 バイト、*(p+1) = 200
p + 2   // アドレス + 8 バイト、*(p+2) = 300
p + 3   // アドレス + 12 バイト、*(p+3) = 400
```

演算の結果は**バイト数ではなく値**です。

### char * では 1 バイト進む

```cpp
char carr[4]{'a', 'b', 'c', 'd'};
char * cp = &carr[0];

cp + 1  // アドレス + 1 バイト
cp + 2  // アドレス + 2 バイト
```

指す型が変わると、ポインタ演算の歩幅が変わります。

## 5.3 配列走査

ポインタ演算を使って配列の要素を順に処理できます。

```cpp
int arr[5]{1, 2, 3, 4, 5};
int * p = arr;

for (int i = 0; i < 5; ++i) {
  std::cout << *(p + i) << " ";  // または arr[i] と同じ
}
```

`arr[i]` は `*(arr + i)` の短記法です。

## 5.4 境界外アクセス

配列の範囲を超えてアクセスすると、**undefined behavior** になります。
AddressSanitizer（`-fsanitize=address`）で検出できます。

```cpp
int arr[2]{1, 2};
int * p = &arr[0];
std::cout << *(p + 2);  // 範囲外！
```

コンパイル:
```bash
g++ -fsanitize=address basics05_oob.cpp -o basics05_oob && ./basics05_oob
```

## 5.5 配列を関数に渡す

配列を関数に渡すと、サイズ情報が失われます。

```cpp
void print_array(int * arr, int size) {
  for (int i = 0; i < size; ++i) {
    std::cout << arr[i] << " ";
  }
}

int data[5]{10, 20, 30, 40, 50};
print_array(data, 5);  // サイズを別途渡す必要がある
```

配列は暗黙的に `int *` に decay するので、関数内では**サイズが分かりません。**
だから、サイズを別途引数で渡すのが慣例です。

**モダン C++ では `std::array<int, 5>` や `std::vector<int>` を使うことが推奨されます。**

## 5.6 参照とポインタの使い分け

以下の判断表を参考に、参照とポインタを使い分けます。

| 状況 | 参照 | ポインタ | 理由 |
| --- | --- | --- | --- |
| 必ず存在する | ○ 推奨 | △ | シンプル。null チェック不要 |
| null の可能性がある | ✗ | ○ 必須 | オプショナルを表現できる |
| 再指向（切り替え）が必要 | ✗ | ○ 必須 | リスト走査など |
| 配列走査・ポインタ演算が必要 | △ | ○ 必須 | 演算ができるのはポインタのみ |
| 呼び出し側の記法を「普通の変数」に見せたい | ○ 推奨 | △ | 参照は `f(a)` で呼べる |

## 5.7 モダン C++ への移行

生のポインタ（`int *`）を直接使う場面は、モダン C++ ではほぼありません。
代わりに以下を使います。

| 用途 | 生ポインタ | モダン C++ |
| --- | --- | --- |
| 配列 | `int arr[10]` | `std::vector<int>` または `std::array<int, 10>` |
| 動的確保 | `int * p = new int(5)` | `std::unique_ptr<int>` または `std::shared_ptr<int>` |
| オプショナルな値 | `int * p = nullptr` | `std::optional<int>` |

詳しくは C++ 編 6 章「スマートポインタ」を参照。

## つまずきポイント

**「ポインタ演算でなぜ 1 ではなく型のサイズだけ進むのか」**

これは C++ の設計です。`p + 1` は「次の要素」を意味するよう、型のサイズだけ進みます。
バイト単位の低レベルな操作が必要なら、`(char*)p + 1` のようにキャストします。

**「配列とポインタはどう違うのか」**

配列は固定サイズで、ポインタは後から何でも指せます。decay により配列名はポインタに変換されますが、`sizeof` は異なります。

**「生ポインタを使わないほうが良いなら、なぜ学ぶのか」**

既存のレガシーコード（C スタイルの関数、古い C++ ライブラリ）には生ポインタが多く出てきます。
読む能力は必須ですが、新規コード（特に ROS 2）では `std::vector` や `std::shared_ptr` を使いましょう。
