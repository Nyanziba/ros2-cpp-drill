# 2. スコープと寿命

> **この章のねらい**: `{` で始まるブロックを抜けると、そこで宣言した変数は消えます。いつ消えるのか、どういう順序で消えるのか、を知らないと 3 章以降で参照やポインタが「なぜ使えなくなったのか」という現象が起きます。
> この章は 3〜5 章の前提になります。軽く読まずに、コンストラクタ・デストラクタの出力をしっかり確認してください。

## 2.1 ブロックスコープ

C++ では、`{` から `}` が 1 つのブロックです。ブロック内で宣言した変数は、ブロックを抜けると**存在しなくなります。**

```cpp
{
  int x = 10;
  std::cout << x << "\n";  // OK
}
std::cout << x << "\n";    // エラー：x は存在しない
```

これを**ブロックスコープ（block scope）**と言います。

## 2.2 自動記憶期間（automatic storage duration）

ブロック内で宣言した変数は、自動的に管理されます。

- **生成**: 変数が宣言された場所で（コンストラクタが呼ばれる）
- **破棄**: ブロックを抜けるとき（デストラクタが呼ばれる）

この仕組みが**自動記憶期間（automatic storage）**です。

## 2.3 破棄の順序は逆

複数の変数がブロック内にあれば、**逆順で破棄されます。**

```cpp
{
  Logger a("a");     // 1番目に構築
  Logger b("b");     // 2番目に構築
  Logger c("c");     // 3番目に構築
}
// 破棄: c → b → a （逆順）
```

このルールはスタック（後入先出）の性質から来ています。

## 2.4 ネストしたブロック

内側のブロック内で宣言した変数は、内側が閉じるときに破棄されます。

```cpp
{
  Logger outer("outer");    // 1番目に構築
  {
    Logger inner("inner");  // 2番目に構築
  }
  // inner は破棄される
  // outer はまだ生きている
}
// outer が破棄される
```

## 2.5 return による破棄

関数から `return` すると、スコープを抜ける直前に変数が破棄されます。

```cpp
void example() {
  Logger local("local");
  // ... 処理 ...
  return;  // local が破棄される
}
```

すべての exit path（`return`、例外、スコープの終了）で破棄されます。

## 2.6 シャドーイング

内側のスコープで外側と同じ名前の変数を宣言すると、内側が外側を隠します。

```cpp
{
  int x = 1;
  {
    int x = 2;  // 内側の x が外側の x を隠す
    std::cout << x;  // 2
  }
  std::cout << x;  // 1
}
```

**コンパイラの警告 `-Wshadow` でこれを検出できます。**

## 2.7 RAII の基礎

C++ では、オブジェクトの生成と破棄を使ってリソース（メモリ、ファイル、ロック）を自動管理します。
これが **RAII（Resource Acquisition Is Initialization）** の原則です。

この章で学んだ自動破棄の仕組みが、RAII を支えています。

## 手元で試す

**ブロックスコープと破棄の順序をコンストラクタ・デストラクタで可視化します。**

```cpp
// basics02_practice.cpp
#include <iostream>

struct Logger
{
  const char * name;

  Logger(const char * n) : name(n)
  {
    std::cout << "[ctor] " << name << " created\n";
  }

  ~Logger()
  {
    std::cout << "[dtor] " << name << " destroyed\n";
  }
};

int main()
{
  std::cout << "=== スコープと寿命 ===\n\n";

  std::cout << "--- 1. ブロックスコープ ---\n";
  {
    Logger a("a");
    std::cout << "a is alive in inner block\n";
  }
  std::cout << "a is now dead (exited block)\n\n";

  std::cout << "--- 2. 生成順と破棄順（逆順） ---\n";
  {
    Logger x("x");
    {
      Logger y("y");
      {
        Logger z("z");
        std::cout << "x, y, z all alive here\n";
      }
      std::cout << "z was destroyed (reverse order: z -> y -> x)\n";
    }
    std::cout << "y was destroyed\n";
  }
  std::cout << "x was destroyed\n\n";

  std::cout << "--- 3. return により破棄される ---\n";
  {
    Logger before("before_return");
    std::cout << "about to return...\n";
  }
  std::cout << "before was destroyed when block ended\n\n";

  std::cout << "--- 4. シャドーイング（内側の変数が外側を隠す） ---\n";
  {
    int x = 1;
    std::cout << "outer x = " << x << "\n";
    {
      int x = 2;
      std::cout << "inner x = " << x << "\n";
    }
    std::cout << "back to outer x = " << x << "\n";
  }
  std::cout << "\n";

  std::cout << "--- 5. 複数変数の逆順破棄 ---\n";
  {
    Logger first("first");
    Logger second("second");
    Logger third("third");
    std::cout << "all three alive here\n";
  }
  std::cout << "destroyed in reverse: third, second, first\n\n";

  std::cout << "--- 6. 関数スコープ ---\n";
  auto test_function = []() {
    Logger func_local("func_local");
    std::cout << "inside function\n";
  };
  std::cout << "calling function:\n";
  test_function();
  std::cout << "function returned, func_local was destroyed\n";

  return 0;
}
```

**予想: constructor と destructor の呼び出し順序を追いながら、どの順で生成され、逆順で破棄されるか確認してください。**

```bash

```

## つまずきポイント

**「ブロックを抜けたら変数が消える」をまだピンときていない**

「消える」とは、その変数のメモリ領域が再利用可能になるという意味です。
デストラクタが呼ばれて後片付けが行われます。
5 章の「ダングリングポインタ」につながる重要な概念です。

**破棄順序が逆なのはなぜ？**

ブロック内の変数はスタック上に置かれます。スタックは後入先出なので、最後に追加されたものが最初に取り出されます。
これは C、C++ のメモリ管理の根本です。

**シャドーイングを避けるには**

異なる名前を使うか、コンパイラの `-Wshadow` フラグで警告させます。
ドリルはテストで `-Wall -Wextra` が有効なので、シャドーイングは避ける習慣を付けてください。
