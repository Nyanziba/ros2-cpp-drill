# 9. 値のセマンティクス

> **この章のねらい**: **C++ では `b = a;` は値をコピーします。** Python や Java では参照を代入するため、その後 `a` を変えると `b` も変わります。C++ はこの点で大きく異なります。この「値のセマンティクス」を理解すると、C++ のコードの動きが予測可能になります。

## 9.1 代入はコピー — `b = a;` のあと `a` を変えても `b` は変わらない

```cpp
#include <iostream>

class Value {
public:
  Value(int x) : x_(x) {}
  
  int x_;
};

int main() {
  Value a(10);
  Value b = a;     // コピー
  
  a.x_ = 99;       // a を変える
  
  std::cout << "a.x_ = " << a.x_ << "\n";  // 99
  std::cout << "b.x_ = " << b.x_ << "\n";  // 10（変わらない）
  
  return 0;
}
```

[▶ ブラウザで実行する（gcc 13.3）](https://godbolt.org/z/93vrP4s4h)

```
a.x_ = 99
b.x_ = 10
```

`a` と `b` は **独立した 2 つのオブジェクト。** `a` を変えても `b` に影響しません。

## 9.2 Python / Java との違い

Python や Java では：

```python
a = Value(10)
b = a            # 参照を代入
a.x = 99
print(b.x)       # 99（変わる）
```

C++ は：

```cpp
Value a(10);
Value b = a;     // 値をコピー
a.x_ = 99;
std::cout << b.x_ << "\n";  // 10（変わらない）
```

**この違いが最大の困惑ポイント。** Python/Java からの経験者は「なぜ参照が渡されないのか」と戸惑います。

**C++ では、代入・関数の引数・戻り値に値のコピーが起きます。** 参照が欲しいなら、`&` を明示的に使います。

## 9.3 コピーコンストラクタと代入演算子

**代入には 2 つの場合があります：**

1. **`Value b = a;`**：新しいオブジェクト `b` を作りながら初期化
   → **コピーコンストラクタ** を呼ぶ

2. **`b = a;`**（`b` が既に存在する場合）：既存のオブジェクト `b` に値を上書き
   → **コピー代入演算子** を呼ぶ

```cpp
#include <iostream>

class Value {
public:
  Value(int x) : x_(x) {
    std::cout << "Value(" << x << ")\n";
  }
  
  Value(const Value & other) : x_(other.x_) {
    std::cout << "Value copy constructor, x=" << x_ << "\n";
  }
  
  Value & operator=(const Value & other) {
    std::cout << "operator=, x=" << other.x_ << "\n";
    if (this != &other) {
      x_ = other.x_;
    }
    return *this;
  }
  
private:
  int x_;
};

int main() {
  std::cout << "=== Copy constructor: Value b = a; ===\n";
  Value a(10);
  Value b = a;   // copy constructor
  
  std::cout << "\n=== Copy assignment: b = a; ===\n";
  Value c(20);
  Value d(99);
  d = c;         // copy assignment
  
  return 0;
}
```

[▶ ブラウザで実行する（gcc 13.3）](https://godbolt.org/z/Kbnoj7sdq)

```
=== Copy constructor: Value b = a; ===
Value(10)
Value copy constructor, x=10

=== Copy assignment: b = a; ===
Value(20)
Value(99)
operator=, x=20
```

**コピーコンストラクタは 1 回だけ呼ばれます。** 一方、代入演算子は既存オブジェクトを上書きするので、古いメンバをクリーンアップしてから新しい値を代入します（上の例では省略）。

## 9.4 引数の受け渡し — 値渡しと参照渡し

**関数に値を渡すとき、渡し方によってコピーの有無が変わります。**

```cpp
void process_by_value(Data d) {
  // d はコピー
}

void process_by_const_ref(const Data & d) {
  // d はコピーされない
}
```

```cpp
#include <iostream>

class Data {
public:
  Data(int x) : x_(x) {
    std::cout << "Data(" << x << ")\n";
  }
  
  Data(const Data & other) : x_(other.x_) {
    std::cout << "Data copy constructor\n";
  }
  
  ~Data() {
    std::cout << "~Data(" << x_ << ")\n";
  }
  
private:
  int x_;
};

void process_by_value(Data d) {
  // d was copied
}

void process_by_const_ref(const Data & d) {
  // d was NOT copied
}

int main() {
  std::cout << "=== pass by value ===\n";
  {
    Data a(10);
    process_by_value(a);
  }
  
  std::cout << "\n=== pass by const& ===\n";
  {
    Data b(20);
    process_by_const_ref(b);
  }
  
  return 0;
}
```

[▶ ブラウザで実行する（gcc 13.3）](https://godbolt.org/z/qdfhar8n1)

```
=== pass by value ===
Data(10)
Data copy constructor
~Data(10)
~Data(10)

=== pass by const& ===
Data(20)
~Data(20)
```

**値渡しの場合、コピーコンストラクタが呼ばれます。** `const Data & d` の場合、コピーが発生しません。

**パフォーマンス重視なら `const Data &` を、小さなデータなら値渡しもあります。** 最近のトレンドは「コンパイラが最適化するので、読みやすい方を選ぶ」です。

## 9.5 戻り値の最適化 — C++17 での保証

**関数から値を返すとき、C++17 では戻り値は直接構成されます。**

```cpp
#include <iostream>

class Data {
public:
  Data(int x) : x_(x) {
    std::cout << "Data(" << x << ")\n";
  }
  
  Data(const Data & other) : x_(other.x_) {
    std::cout << "copy constructor\n";
  }
  
  Data(Data && other) noexcept : x_(other.x_) {
    std::cout << "move constructor\n";
  }
  
  ~Data() {
    std::cout << "~Data(" << x_ << ")\n";
  }
  
private:
  int x_;
};

Data create() {
  return Data(40);   // 一時オブジェクト
}

int main() {
  std::cout << "=== Returning by value in C++17 ===\n";
  Data d = create();
  std::cout << "=== Done ===\n";
  return 0;
}
```

```
=== Returning by value in C++17 ===
Data(40)
=== Done ===
~Data(40)
```

**コンストラクタ 1 回だけ。** コピーもムーブも起きません。これを **保証された戻り値の最適化（Guaranteed RVO）** と呼びます。

C++17 以前では、コピーやムーブが起きました。C++17 以降は保証されています。

## 9.6 値のセマンティクス — まとめ表

| 操作 | コピーが起きるか | 例 |
| --- | --- | --- |
| `b = a;` | はい | 値渡しで、新しいコピーが作られる |
| `void f(Data d)` で呼び出し | はい | 関数内の `d` は別のコピー |
| `void f(const Data & d)` で呼び出し | いいえ | `d` は元のオブジェクトへの参照 |
| `void f(Data && d)` で呼び出し | いいえ | `d` は一時オブジェクトへの参照 |
| `return a;` | C++17 以降いいえ | 戻り値の最適化で直接構成 |
| コンテナに `push_back(d)` | はい | コンテナ内でコピーが作られる |

## 手元で試す

コピーコンストラクタ、代入、値渡し・参照渡し、戻り値の最適化を 1 つのプログラムで確認します。

```cpp
#include <iostream>

class Data {
public:
  Data(int x) : x_(x) {
    std::cout << "[constructor] x=" << x << "\n";
  }
  
  Data(const Data & other) : x_(other.x_) {
    std::cout << "[copy constructor] x=" << x_ << "\n";
  }
  
  Data & operator=(const Data & other) {
    std::cout << "[copy assignment] x=" << other.x_ << "\n";
    if (this != &other) {
      x_ = other.x_;
    }
    return *this;
  }
  
  Data(Data && other) noexcept : x_(other.x_) {
    std::cout << "[move constructor] x=" << x_ << "\n";
  }
  
  void print() const {
    std::cout << "value=" << x_ << "\n";
  }
  
private:
  int x_;
};

void show_copy_behavior() {
  std::cout << "== COPY SEMANTICS ==\n";
  std::cout << "Creating a(10):\n";
  Data a(10);
  
  std::cout << "\nCopy: Data b = a;\n";
  Data b = a;
  
  std::cout << "\nNow a and b are independent:\n";
  std::cout << "a: "; a.print();
  std::cout << "b: "; b.print();
}

void pass_by_value(Data d) {
  // d was copied when passed
}

void pass_by_const_ref(const Data & d) {
  // d was NOT copied
}

void show_passing() {
  std::cout << "\n== PASSING BY VALUE vs CONST& ==\n";
  
  std::cout << "Pass by value - creates copy:\n";
  Data a(20);
  pass_by_value(a);
  
  std::cout << "\nPass by const& - no copy:\n";
  Data b(30);
  pass_by_const_ref(b);
}

Data create_data() {
  return Data(40);
}

void show_returning() {
  std::cout << "\n== RETURNING BY VALUE (C++17) ==\n";
  std::cout << "Call create_data() and assign:\n";
  Data d = create_data();
  std::cout << "Only constructor, no copy or move!\n";
}

int main() {
  show_copy_behavior();
  show_passing();
  show_returning();
  
  return 0;
}
```

**予想: コピーコンストラクタが複数回呼ばれるか。値渡しと参照渡しでコピー回数が違うか。戻り値でコピーが起きるか。**

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic try.cpp -o try && ./try
```

## つまずきポイント

**「参照を渡すと思ったのに、値が変わっていた」**
C++ では代入でコピーが起きます。参照（`&`）を使わない限り、値は渡されます。Python の経験がある場合はこの違いに注意。

**コピーコンストラクタと代入演算子の呼び分け**
- `Value b = a;` → コピーコンストラクタ
- `b = a;` （b が既に存在） → 代入演算子

同じ `=` ですが、意味が違います。

**ムーブセマンティクスはまだ必要ない**
C++17 以降なら、戻り値の最適化が保証されているので、ムーブを明示的に使う場面は減りました。
詳しくは [C++編](../cpp/README.md) で。

**大きなオブジェクトを渡すときは `const &` を使う**
コンテナなど大きなデータは `const Data &` で渡し、コピーを避けてください。
